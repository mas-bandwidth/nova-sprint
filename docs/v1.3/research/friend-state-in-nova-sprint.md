# Friend state in nova-sprint: second copies, friend-local reads, and derived presence

The v1.3 spec (mas-bandwidth/nova-tools, docs/spec/v1.3) makes one server the truth for friends: comms live in nova-tools and nova-sprint only consumes them; layer 10 rules out a second mutable roster and compatibility sync loops that remain necessary for correctness; layer 40 guarantee 1 says a friend client's directory holds no inbox, outbox, presence file or epoch flag that anyone reads as authority; layer 50 says the server record owns card state and the author's local checkout owns none of these. Today nova-sprint still does all four things. This inventory names sixteen records: eight are a **second copy** of a friend's truth, four are a **friend-local read** of a file a friend's client wrote on her host, and four are **derived presence** (up, down, held, asleep, working) worked out from a beat, a live set, an observation or a finish time. Each row gives the record with the function that names it, every writer and reader with what the reader decides, the loop or verb that runs it, and what the spec replaces it with. Files under `pkg/friend` and `pkg/bus` here are vendored copies of nova-tools packages; only this repository's uses of them are listed. No person, friend or machine is named.

Four records have **no replacement named** by the quoted layer words: the friend stall ladder's properties, the friend's own work counts on her beat, the bus store's roster of friend names, and the friend's daemon facts (build, started, present) carried on the beat. Every other row has a spec replacement, but in this repository none of those server records exists yet, so each implementation card lands against `not yet built`.

## (a) Records with no replacement named (gaps for the spec owners)

- The friend stall ladder's rungs and stall-down stamps (fleet properties, internal/sprint/friend_stall.go:45): the quoted layer words name no server record for a stalled or idle friend, or for the wakes, take-backs and down-marking the ladder decides.
- The friend's own work counts and daemon facts on her beat (`working`, `queue`, `width`, `paced`, `window`, `load`, `active`, `build`, `started`, `present`, internal/sprint/presence.go:185): they are the daemon's word shown beside the table's, and the quoted layers name no server record for them.
- The bus store's roster of friend names (pkg/bus/redis.go:21): unless nova-bus is the one server of layer 10, this is a second roster with no named replacement.
- The `friend` hold itself: the roster's `held`, reason and until (internal/sprint/store/friends.go) are a coordinator decision the spec words do not place on the server.

## (b) Each replaced record, and the nova-tools record or verb it would read instead

- The friend roster and each width -> a nova-tools friend record read by the deal: `not yet built`.
- The bus store's roster -> the one server's friend records, if nova-tools lands one server: `not yet built`.
- The beat as presence (server binding and proof) -> a nova-tools session binding and proof lease: `not yet built`.
- The health observation -> the same binding and proof record: `not yet built`.
- The finish time -> the server's own card-state record (server assignment): `not yet built`.
- The live set and the running set -> the server's lane record for each friend's running lanes: `not yet built`.
- The QUEUE.json, the inbox brief, the outbox report, the runner log and the job staging -> the server's assignment and lane records the friend client would read and write instead of files: `not yet built`.

## (c) Proposed order to remove them, bottom up

1. `friend-state-reads-the-server-roster-and-width`: the deal, level, take, admission and every display read the friend roster and width from the one server, and `friend sync` only relays config; the store's `friends` key and the bus store's `friends` set are read by nothing.
2. `friend-cards-are-assigned-on-the-server`: a friend's card is delivered and reported as a server assignment and lane record, and no reader opens `inbox/<job>/BRIEF.md` or `outbox/<job>/REPORT.md` to decide anything.
3. `friend-reconcile-reads-the-server-account`: `friend reconcile` and the run loop settle a friend's cards from the server's assignment record, and `inbox/QUEUE.json` is read by nothing.
4. `collect-reads-the-server-lanes`: `collect` and `collect --dead-lanes` finish and fail cards from the server's lane records, and `runner.log` and the job-staging walk are read by nothing.
5. `friend-presence-is-its-session-lease`: up, held and down come from the server's session binding and proof lease, and the beat record, the health observation and the finish time are no longer read as evidence (the beat stays only as the daemon's transport).
6. `friend-live-sets-are-server-lane-records`: the reconcile returns working cards from the server's lane record, and the beat's live set and running set decide nothing.
7. `friend-sync-loops-leave-nova-sprint`: `friend sync`, its `--every` loop, its service unit and `friend sync install` leave once the server is the truth, so no compatibility sync loop is needed for correctness.
