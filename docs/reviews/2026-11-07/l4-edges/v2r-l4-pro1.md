# Cold review: layer 4 (edges), row v2r-l4-pro1 (sonnet)

Scope: `edge/**` (exec, argv, failure, request, bus, git, forge, worker), `cmd/nova-worker/**`, `docs/LAYER-4-EDGES.md`, `docs/SEAMS.md`, models `tla/Runner.tla`, `tla/LandEdge.tla` (+ their Trace modules). Checkout: `43d849e2` (an earlier row's report was on the branch; this one is written over it, its findings re-verified below and kept where they held).

Commands run: `go build ./... && go vet ./...` clean. `go test -race -skip Functional` (the Makefile's unit tier) green for `./edge ./edge/bus ./edge/forge ./edge/git ./edge/worker ./cmd/nova-worker`. A plain `go test` (which also runs the `Functional*` tests, real processes, real `nova-bus`/`nova-reserve`, a throwaway `redis-server`, real time) is red in two places: `TestFunctionalNovaBusWhoAndSend` (`edge/bus/functional_test.go:110`, "expected sprint and amd-1.ds in nova-bus who", reproducible, probably this host's nova-bus) and `TestFunctionalBreakShippedWorkerRunsHarnessOutsideAnySlot` (`cmd/nova-worker/break_test.go:80`, stale, see defect 11). I probed with throwaway tests (deleted, nothing else changed in the tree); their output is quoted per defect.

## Verdict

The layer is well structured and its unit tier is green under the race detector, but it is not sound as a wall: the worker runs `git` outside the wall in a repository whose `.git/config` the harness can write, so a card can execute code as the worker with one file write (defect 1). Around that sit six serious reliability gaps on the paths the doc calls its core promises: restart adoption works only where `/proc` exists (the fleet has Macs), a worker stop or a missing slot during the card's tests is reported as a red test and bounces the card, `ErrNoSlot` is detected by a substring of the harness's own output, permanent verb failures are swallowed as "store down" with no log line, an unreadable `job.json` silently wedges its card, and the key proxy buffers streaming responses. The single worst thing is defect 1.

## Defects

Ranked; severity then breadth.

1. **[blocker] A harness can run code outside the wall through the repository config the worker's git reads.** `edge/worker/runner.go:1056-1067` (`OSGitOps.runGit_internal`) runs `git` in the job worktree with only `-c core.hooksPath=/dev/null -c core.fsmonitor=false`. The worktree and its `.git/config` are inside the job directory, which the wall grants `--write` (`harness.go:374`), and the worker runs `status`, `add -A`, `commit`, `rebase`, `push`, `remote get-url` there after the harness exits (`runner.go:1039-1052`, `994-1022`), outside the wall, as the worker's uid. Config-borne commands (`filter.<n>.clean`/`smudge`/`process`, `credential.helper`, `core.sshCommand`, `diff.*.textconv`, `merge.*.driver`) are not neutralised; `.gitattributes` is committed content the harness also writes. Reproduced with the exact flags (scratch repo, `.git/config`: `filter.x.clean = sh -c 'touch .../PWNED; cat'`, `.gitattributes`: `* filter=x`): `env -i ... git -C wt -c core.hooksPath=/dev/null -c core.fsmonitor=false add -A && ls` printed `PWNED`. Why it matters: Guarantee 12 ("No key or DSN is in the wall's environment or files") and "A card can never ... reach the store or the bus ... write outside its job directory" stop being true for any prompt-injected or hostile card: the escaped child can read the parent's environment (`/proc/<ppid>/environ` on Linux, same uid), which under the bench seat holds the sprint credentials (`serve.go` comment, `verbs.go:82-86`). Repair: before the worker's first git call after the harness exits, rewrite `<wt>/.git/config` from a known template (origin url, user.name/email only), delete `.git/info/attributes` and every `.gitattributes`-driven filter by running git with `-c core.attributesFile=/dev/null` plus `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null`, or run those git steps inside a second wall.

2. **[serious] Restart adoption (`Alive`/`Kill`) exists only where `/proc` does; on macOS a restart starts a second harness on a live card.** `edge/worker/runner.go:93-104`: `Alive` is true only for `liveProcNonces_internal` (empty after a restart) or a `/proc/<pid>/environ` containing `NOVA_WORKER_NONCE=`; `Kill` returns at once when `Alive` is false (`105-108`). Reproduced on this Mac: a live child started with `NOVA_WORKER_NONCE=nz` gives `Alive(pid, "nz") = false`. Consequence after a worker crash (children survive, `Setpgid`): `recoverWorkingJob_internal` (`recover.go:122`) never adopts, falls to "resume" (`recover.go:126`, `prepareResume_internal` default branch), and runs the card again beside the orphan, breaking Guarantee 7 ("One live harness per job directory") and the model's `OneLiveHarnessPerJobDir`; a withdrawn orphan can never be killed (`withdrawRunningJob_internal` -> `Kill` no-op). The only nonce test (`coldread2_test.go:130-135`) is negative; nothing asserts a positive `Alive`. Repair: portable liveness (`ps -o command= -p <pid>`/`kern.procargs2`, or a pid-file lock held by the wall's child) and a positive-case test on every OS the fleet runs.

3. **[serious] The card's tests are run with errors folded into "tests red", so a worker stop or a missing slot bounces the card.** `edge/worker/runner.go:676-686`: `if tres, err := r.Wall.RunTest(...); err != nil || tres.ExitCode != 0 { rec.Outcome = Outcome{Result: "fail", ...}`. `err` includes `ErrNoSlot` (doc: "no slot within the wait is no start yet, never a failure") and `context.Canceled` (the worker's own stop; doc: "A job the worker's own stop cuts short is 'runner stopped': not reported"). Reproduced with a stub wall: `wall err=worker: no nova-reserve slot ... -> outcome=fail "tests red (true): worker: no nova-reserve slot available within wait:"` and `wall err=context canceled -> outcome=fail "tests red (true): context canceled:"`. The fail is written to `job.json` (`runner.go:684`) while `State` stays `harvested`, so after a restart `rebaseAndTestStep_internal` returns early (`runner.go:651`, Outcome is not "ok") and the persisted fail is reported: a graceful `SIGTERM` during tests spends a bounce, violating Guarantee 11. Repair: return `ErrNoSlot` and a `ctx.Err()`-aware `stopped_internal` from the test loop, and treat only `ExitCode != 0` with a nil `err` as red.

4. **[serious] `ErrNoSlot` is decided by a substring of the harness's own output; a harness that exits 1 and prints `nova-reserve:` is re-run forever.** `edge/worker/runner.go:1161-1163`: `ExitCode == 1 && strings.Contains(combined, "nova-reserve:") && !strings.Contains(combined, "nova-reserve: HELD")`, where `combined` is the wrapped harness's stdout+stderr. `nova-reserve help` says exit 1 is "refused (no slot within --wait ...)" and "else the command's status", so the harness's own exit 1 is indistinguishable by code. Reproduced with a fake exec (`exit 1`, stdout "the card quoted nova-reserve: wait expired"): `ErrNoSlot=true`. `runAndHarvest_internal` then returns the error with the job left `staged` (`runner.go:550`, `pass.go:431-432`), the next pass runs the harness again, consuming model budget with no attempt spent, indefinitely. Any card about nova-reserve (this repository's own) or whose agent quotes the tool is a trigger. Also exit 2 ("could not run") and any non-125/126/127 wall refusal become `fail: no verdict` (`runner.go:571`), bouncing for a bench fault. Repair: match only the first line of `res.Stderr` the wall itself wrote before the harness started, or have nova-reserve use a dedicated exit code, and add 2 to the infra list.

5. **[serious] Permanent `nova-sprint` failures are classified "store down" and dropped without a log line.** `edge/worker/verbs.go:121-124`: every non-1 exit, a missing binary, a usage error (2), `E2BIG` is `ErrStoreDown`; `edge/worker/pass.go:150-155,168` (`ignoreStoreDown_internal`) turns that into `nil`; `wakeLoop_internal` logs only non-nil pass errors (`pass.go:85-86`); `resendErr_internal` returns silently on it (`recover.go:213`). A `nova-sprint` upgrade that changes a flag (exit 2) or an argv over the kernel's 128 KB per-arg limit (`Finding`/`Reason` from `result.json` are passed unbounded, `verbs.go:207-210`, `harness.go:292,315`) makes the worker idle or retry forever, saying nothing. Repair: treat only a connect-class failure as store-down, log each distinct swallowed cause once (as `beat_internal` does), and cap `Reason`/`Finding` before they reach argv.

6. **[serious] An empty or corrupt `job.json` is skipped silently and its card never launches.** `edge/worker/runner.go:233` (`ReadJobRecord` error ignored) and `edge/worker/pass.go:216` (`fileExists_internal(jobs/<id>)` skips the launch). `WriteJobRecord` (`worker.go:119-132`) renames without `fsync`, so an OS crash can leave a zero-length file. Reproduced: an empty `jobs/c1/job.json` gives `loaded=0 err=<nil>; dir exists ... =true`. The consumer stays `working` in the row's hand with no process, no log, and (see `recover.go:262-264`) no escalation. Repair: log and quarantine an unreadable record, `fsync` the temp file and directory before the rename.

7. **[serious] `SlotWeight` is never set, so `--slots` is never sent.** `edge/worker/worker.go:74` declares it, `edge/worker/harness.go:356-358` emits `--slots` only when `> 0`, and nothing outside tests assigns it (the one write is `worker_test.go:305`). LAYER-4 step 4 and Guarantee 8 / "width and slots are separate counts" promise `nova-reserve run --slots <weight>`; every job holds `nova-reserve`'s default of one slot (`nova-reserve help`). Verified independently of the earlier row; same repair: carry a weight in the take receipt or policy, or delete the field and say the default.

8. **[serious] Landed is recorded without the promised ancestry check, and the merge method can make it unprovable.** The doc (git edge step 7) promises "each landed head is checked an ancestor of the pushed base tip (LPM M21)". `edge/git/land.go:223-228` sets `LandedHeads = Heads` straight after `fg.Merge`; `grep -rn M21` finds no code. `forge.method_internal` (`forge.go:465-495`) takes the first of merge, squash, rebase the repository allows, so on a squash-only repository the heads are never ancestors of base: the next pass's `allAncestors_internal` (`land.go:85`) cannot recognise an already-landed group and re-merges it onto a base that holds its squash. Repair: after `Merge`, fetch base and require `IsAncestor(head, baseTip)` for every head (or refuse squash/rebase streams at `stream add`, as the doc does for unprotected bases).

9. **[serious] A merge that succeeded but whose read-back failed is reported "GitHub refused the merge".** `edge/forge/forge.go:443-449` runs `gh pr merge` then `gh pr view`; a failure of the second (rate limit, timeout) returns an error although the PR is merged, and `edge/git/land.go:223-227` maps every `Merge` error to `OutcomeRefused` ("GitHub refused the merge of ..."). Layer 3 opens a `land` judgement for a landing that happened; with defect 8 on a squash repository no later pass can reconcile it. Repair: on a read-back error, re-ask `pr view` (rest, then retry) and return a distinct `merged-unconfirmed` outcome that layer 3 treats as pending.

10. **[serious] The key proxy buffers streaming responses.** `edge/worker/proxy.go:268-270` copies with `io.Copy(w, io.LimitReader(...))` and never flushes. Reproduced with an SSE upstream that sends one event at 0 s and the next at 1.5 s: the client's first read returned `"data: one\n\ndata: two"` after 1.5 s. The opencode route (and any API-rate model) streams tokens; a harness with an idle-stream timeout sees silence, and the 16 MB `LimitReader` cuts a long stream mid-body after sending the upstream's `Content-Length` (copied by `maps.Copy`, `proxy.go:268`), which the harness reads as a protocol error. Repair: flush after each read (`http.NewResponseController(w).Flush()`), drop `Content-Length`/hop-by-hop headers, and end the stream with an error rather than a silent cut.

11. **[serious] The only functional guard for Guarantee 8 is stale and red.** `cmd/nova-worker/break_test.go:59` deals the consumer in `ready`, but the worker launches only `next.Working` (`edge/worker/pass.go:215-222`), so nothing is taken and the assertion at `break_test.go:91-93` is never reached: `no report reached nova-sprint (exit 0 ... sprint log "unhook ... hook ... beat ... next ... next")`. Confirmed independently of the earlier row. Repair: deal it under `working` and assert the recorded wall argv starts `nova-reserve ... run`.

12. **[minor] A rebase that fails for a reason other than a conflict is reported `fail` (a bounce), not `fault`.** `edge/worker/runner.go:667-669` (`default:` branch: "rebase failed: ...") fed by `OSGitOps.RebaseOntoStream` returning a bare error when `diff --diff-filter=U` lists nothing (`runner.go:1013-1019`): a dirty tree, a locked index, a full disk spend an attempt. Guarantee 11 says bench faults spend none. Repair: only a `ConflictError` is a fail; everything else a fault.

13. **[minor] Worker pushes use whatever git credentials the host's `HOME` holds, not the row's token.** `edge/worker/runner.go:994-1000,1058-1061`: `git push` with `HOME` from the environment and no helper; no `Token` anywhere in `edge/worker`. The doc says "Workers push and open PRs with their row's token" and "The git token is used only by the runner" (LAYER-4, Credentials and step 5), and the git edge itself resets the helper list precisely "so a person's keychain never answers for the sprint" (`edge/git/url.go:77-91`). Repair: give `OSGitOps` the same `tokenEnv_internal`/`credentialEnv_internal` environment.

14. **[minor] One process-wide "last provider status" register is shared by every concurrent job.** `edge/worker/proxy.go:31,35-45` (`lastStatus`), consumed with `Swap(0)` by whichever job finishes first (`runner.go:559`, `585`; `probe.go:203`), then used to override a missing verdict (`harness.go:296-299`). With width above one, job A's provider 429 can be consumed by B (A then bounces as `fail: no verdict`), or B's early 5xx turns A's unrelated failure into a fault. Repair: record the status per job (a per-job route prefix or header) rather than per proxy.

15. **[minor] `CLISprintClient.Epoch` is read and written from several goroutines with no lock, and `Release` uses the current epoch, not the record's.** `edge/worker/verbs.go:143` (written in `Next`), `149`, `201`, `224` (read). Reproduced with `go test -race`: `WARNING: DATA RACE ... Write ... (*CLISprintClient).Next verbs.go:143 ... Previous read ... Release verbs.go:224`. Passes (`Next`), detached jobs (`Take`/`Report`/`Release`) and the beat loop run concurrently by design (`pass.go:70,174`). `Release(...)` has no epoch parameter, so `releaseNoBlame_internal` (`recover.go:192`) for an old-epoch record asks the store to release the same-named consumer of the current epoch. Repair: guard the field and pass `rec.Epoch` to `Release`.

16. **[minor] Cost is never recorded for the real harnesses.** `Usage` is `readUsageFile_internal` (`harness.go:88,324-331`), and only the test double writes `usage.json` (`harness.go:189`); claude, codex and opencode never do, so every real report carries `--cost-microusd 0 --priced false` (`verbs.go:205`). A harness-written file is also trusted unvalidated. Repair: read the harness's own accounting, or say in the doc that cost is not recorded yet.

17. **[minor] A leftover job directory from an earlier epoch (or a retire whose removal did not finish) wedges the redealt card.** `edge/worker/pass.go:216` skips any card whose `jobs/<id>` exists; `recover.go:68-71` only retires a lower gen of the same epoch, an epoch mismatch hits `identity-mismatch-kept` (`recover.go:70-71`) on every pass; `retire.go:94-96` returns when the retired record exists, so a crash between its write (`retire.go:99`) and the removal (`100`) leaves the directory for good. Consumer ids repeat across epochs (`retire.go:67-69`). Repair: retire by epoch, and make `retireJob_internal` retry the removal when the directory is still present.

18. **[minor] `CleanEnv: true` with a nil `Env` inherits the whole environment.** `edge/exec.go:120-121` (`slices.Clone(nil)` is nil, and `exec.Cmd.Env == nil` means "inherit"). Reproduced: `Cmd{Argv: {"/usr/bin/env"}, CleanEnv: true}` printed the process environment; `Env: []string{}` printed nothing. All current callers pass a non-empty `Env`, so it is latent. Repair: `c.Env = append([]string{}, cmd.Env...)`.

19. **[minor] The git edge calls every non-zero `fetch` "ref not on origin".** `edge/git/git.go:150-152` wraps any exit code in `ErrMissingRef` (auth failure, DNS, protocol error alike). Landing treats `missing_head` as a card-side problem (`land.go:81`), `LsRemote` by sha fetches every remote tip to answer (`git.go:226-240`, O(refs) fetches of 60 s each). Repair: distinguish "couldn't find remote ref" (stderr) from other failures.

20. **[minor] `X-Target-Host` lets the harness pick the upstream port, and nothing authenticates the proxy's callers.** `edge/worker/proxy.go:217-223` replaces `base.Host` and validates only the hostname part (`api.good.com:9999` reproduced as `https://api.good.com:9999/v1/chat ... Authorization: Bearer <key>`); the placeholder key is never checked (`proxy.go:251-256`), so any local process on the bench can spend the real key through `127.0.0.1:<port>`. Repair: delete the header (no route needs it) and require a per-job token in place of the placeholder.

21. **[minor] The probe's judgement opener calls a verb that does not exist.** `edge/worker/probe.go:60` -> `edge/worker/verbs.go:231-234` (`judge-open`); no such verb in `verbs/` (`verbs/table_coordinate.go:15` has only `judge`). Every failed probe appends "and its judgement could not be opened" and none is created. Verified independently of the earlier row; repair: add the verb in layer 6 or drop the call.

22. **[nit] `Runner.QueryEdge`/`evalEdgeQuery_internal` and `edge.Deduplicator` have no production caller.** `edge/worker/runner.go:762-791` and `edge/request.go:43-101` are reached only from tests (`NewDeduplicator` is called once, `runner.go:186`, to feed `QueryEdge` alone). Why it matters: dead surface in a layer meant to be tight, with its own tests to keep. Repair: delete `QueryEdge`, `evalEdgeQuery_internal`, `Deduplicator` and their tests until layer 6 calls them.

22b. **[nit] `Deduplicator.Do` leaves its key in flight forever if `fn` panics.** `edge/request.go:92-100`: `delete(d.inflight, key)` and `close(call.done)` run after `fn` returns, not in a `defer`, so a panic skips both and every later caller of that key blocks until its own context ends. Why it matters: a latent hang should the type ever get a caller. Repair: move the delete-and-close into a `defer` registered before `fn` is called (moot if 22 is taken).

23. **[nit] `ParseGate` splits at newlines.** `edge/argv.go:67` (`unicode.IsSpace`) makes a two-line DONE-WHEN one argv with the second command as arguments, contrary to "one command"; refuse a line holding `\n`.

24. **[nit] The ledger line-union merge keeps a line any side still has, so a deletion on one side is undone.** `edge/git/git.go:375-389` (`unionLines_internal`) takes the union of `:2:` and `:3:` with no base (`:1:`), so a line removed by one head and kept by the other (or a line both changed, old and new together) comes back; this is a defect only against the doc's "merged entry by entry" (`docs/LAYER-4-EDGES.md:137`) and `docs/LESSONS.md:69`, whose motivating case is `BASE-REDS.md` row deletions. Why it matters: deleting a ledger row is silently lost at landing. Repair: do a three-way line merge using `:1:` (drop a line the base had and either side removed) before the union.

The format question is not decided cold: whether sexp or JSON ledgers (fixes.sexp, roadmap) are one entry per line, and so whether a line union can ever be valid for them, is a question for the coordinator (added below), not a defect.

## Promise gaps

- LAYER-4 step 4, "Run under `nova-reserve run --slots <weight>`": `--slots` is never emitted (defect 7).
- Guarantee 11, "A fault ... spends no attempt and no bounce": a stop or missing slot during tests, and a non-conflict rebase failure, are `fail` (defects 3, 12).
- Guarantee 7, "One live harness per job directory": breaks after a crash on any host without `/proc` (defect 2).
- Guarantee 12 / "A card can never ... write outside its job directory": repository config executes outside the wall (defect 1).
- Git edge step 7, "each landed head is checked an ancestor ... (LPM M21)": no such check (defect 8).
- "no slot within the wait is no start yet, never a failure": true for the harness only via a substring match that a harness can trigger or evade (defect 4); false for the test run (defect 3).
- "Workers push ... with their row's token": host credentials (defect 13).
- Guarantee 13 and "Timeouts, each a policy number": the worker's, git's, forge's and bus's timeouts are Go constants (`edge/worker/worker.go:51-59`, `serve.go:84`, `edge/git/git.go:17-20`, `edge/forge/forge.go:24`, `edge/bus/bus.go:20`); only a card's deadline comes from policy.
- Git edge step 3, "Push the merge to `sprint/<stream>`": the code pushes `sprint-group/<stream>` (`edge/git/git.go:443`, `land.go:166-190`); the doc is stale.
- "Restart loses nothing" / `job.json` record: not synced to disk (defect 6).
- "the wall lets it reach only that port" (key proxy): true for opencode only; claude and codex run `NetOpen` (`harness.go:108,114`), as the doc admits ("weaker and is shown as such on the row"); I did not find where the row shows it.
- Guarantee 10, "recorded at most once per result id": kept (`FormatResultID` is stable, `runner.go:726-729` requires a matching op).

## Model vs code

- `Runner.tla` has no action for the step where DONE-WHEN is run (`Rebase` and `Conflict` only, `Runner.tla:139-155`), so the test-red / no-slot / stopped outcomes of defect 3 are outside the model and the trace walk; add a `TestRed`/`TestNoSlot` action with `StopIsNeverAFault` over it.
- `Runner.tla` treats `harnessAlive` as ground truth (`Runner.tla:107-128`) and `Restart` adopts by pid; the code derives it from an OS-specific nonce check (defect 2), so `OneLiveHarnessPerJobDir` holds in the model on every OS and in the code on Linux only. The trace walk uses a fake `ProcessTable`, so the bound is never exercised on the real one.
- `Runner.tla` has no unreadable-record state (defect 6) and no epoch (defect 17).
- `Runner.tla` `Run` is disabled when `slotsInUse = MaxSlots` (a stutter); the code's `ErrNoSlot` path rewrites `State` to `staged` and writes the record (`runner.go:549-553`), an action the model never takes, and is entered on a text match (defect 4).
- `LandEdge.tla` models an absent CI as a terminal refusal; the code re-asks `ci_absent` until `Wait` (run/edges.go), as documented, so the code is a superset. It has no merge-method or post-merge-ancestry action, so defects 8 and 9 are outside it; `GitHub refuses` is the only model of a failed merge, which hides "merged but unconfirmed".
- Earlier row's observation that `Runner.tla` `Clean` needs `pushed` while the code cleans an unpushed record (`runner.go:737-746`) is true and benign; the model is stricter.

## Questions for the coordinator

- What does `nova-reserve run` print when `--wait` expires with no free slot (the doc and `runner.go:1161` assume a `nova-reserve:` prefix; the code excludes `nova-reserve: HELD`)? If the `HELD` form is the wait expiry, defect 4's exclusion routes the real no-slot case to a harness fail.
- Where is a job's slot weight meant to come from (receipt, policy, roster)? No seam carries one today (defect 7).
- Is `claude`/`codex` on `NetOpen` with a writable config directory an accepted trade for the cards the fleet runs (defect 1 raises the cost of that trade)? Should the worker's git steps run inside the wall?
- Which merge methods must landing support? If squash/rebase are allowed, M21 cannot be an ancestry check and the "landed" recognition on a later pass (`land.go:85`) needs a different test (defects 8, 9).
- Are the macOS benches expected to survive a worker restart with harnesses adopted, or is a restart on macOS allowed to rerun (defect 2)?
