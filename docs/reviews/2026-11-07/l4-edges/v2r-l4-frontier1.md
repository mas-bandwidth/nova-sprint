## Verdict

The four small edges (exec, bus, forge, git) are mostly sound and read well; the runner is where the layer does not keep its own promises. The single worst thing: a worker stop (every service restart or deploy) that lands while a job is in its rebase-and-test step is written to the record as the card's `fail` ("tests red ... context canceled") and sent as such after the restart, so a stop spends the card's attempt and blames the head (reproduced below). Beside it, on a darwin bench a restarted worker cannot see a live harness at all (`/proc` is Linux-only, the nonce table is in memory) and starts a second harness on the same job directory (reproduced). The landing has two gaps at the merge: a PR GitHub merged but whose merge commit could not be read is answered `merge_refused` with base already moved, and under a squash or rebase merge method the heads never become ancestors of base, which the doc's step 7 and the next pass's `allAncestors` assume. The rest is a long tail of stale doc sentences, numbers reused for things they were not measured for, and about 400 lines of code with no caller.

## Defects

Ranked, most severe first. Severity in brackets.

1. **[blocker] A worker stop during the rebase-and-test step is reported as the card's `fail` after the restart.** `edge/worker/runner.go:678-686`: when `RunTest` returns an error (the job's context cancelled by the worker's stop), the record's outcome is set to `fail`, "tests red (<cmd>): ... context canceled", and written to disk; `runner.go:656-672` does the same for the rebase's fetch (a `fault`). Neither branch checks `ctx.Err()`. The send that follows fails (the cancelled exec is `ErrStoreDown`, `pass.go:406-410`, `recover.go:213`), so the record stays at `reporting`/`harvested` with that outcome, and the next start resends it (`recover.go:119-121`) or skips the rebase because the outcome is not ok (`runner.go:651`) and sends it. The stop path that keeps a job (`pass.go:444-451`, `stopped_internal`) is reached only from the staging and run branches (`pass.go:379-389, 429-430`). Promise broken: "A job the worker's own stop cuts short is 'runner stopped': not reported, kept to resume" (doc, Results paragraph and w3W item 73), guarantee 11, and `Runner.tla:402-405` `StopIsNeverAFault`. Reproduced with a throwaway test (fake sprint whose `Report` fails on a cancelled context, as the CLI client does; fake wall whose `RunTest` blocks until the stop; a restart on the same root):

   ```
   go test -count=1 -run TestReviewProbe -v ./edge/worker
   zz_review_probe_test.go:65: after the stop: reports=0 record state=reporting outcome={Result:fail Head:2222... Reason:tests red (go test ./...): nova-sandbox: context canceled: ...}
   zz_review_probe_test.go:71: reported after the restart: result=fail head=2222... reason="tests red (go test ./...): nova-sandbox: context canceled:"
   --- FAIL: TestReviewProbeStopDuringTestRerun (0.08s)
   ```
   Repair: in `rebaseAndTestStep_internal`, when `ctx.Err() != nil` after the fetch, the rebase or a gate, write nothing and return `stopped_internal`'s keep (state `harvested`, outcome untouched), so the resume reruns the rebase and the gates; add the same guard before the post-rebase push.

2. **[blocker on darwin and BSD benches] A restarted worker cannot recognise a live harness, and starts a second one on the same job directory.** `edge/worker/runner.go:93-104` `OSProcessTable.Alive`: after `kill(pid, 0)` it needs the nonce either in `liveProcNonces_internal` (in-memory, empty after a restart) or in `/proc/<pid>/environ` (Linux only); on darwin and the BSDs it returns false for every live process. `recover.go:122-124` then does not adopt; `recover.go:168-171` resumes the job at `staged` and `pass.go:415-420` runs the harness again while the first still runs in its slot, both writing the one worktree and `result.json`. Promise broken: "A `working` consumer whose harness is alive is adopted by pid and nonce" (doc, Restart paragraph), guarantee 7 "One live harness per job directory", `Runner.tla:292` (Restart: "adopt live harnesses by pid and nonce, never spawn a second"), witness `RunnerRestartSpawnsSecondHarness`. Reproduced on this host:

   ```
   zz_review_probe_test.go:87: GOOS=darwin pid=3404 ... Alive(pid, nonce)=false
   --- FAIL: TestReviewProbeAliveAfterRestart (0.01s)
   ```
   (a live `sleep 5` started with `NOVA_WORKER_NONCE=n-probe` in its environment, the in-memory nonce dropped as a restart drops it). Repair: record the child's start time in `job.json` at `OnStart` and have `Alive` compare pid plus start time (`ps -o lstart= -p`, or `sysctl kern.proc.pid` on darwin, `/proc/<pid>/stat` field 22 on Linux); or on darwin read the environment with `ps -E -o command= -p <pid>` (works for the worker's own uid). Until then the worker must refuse to resume a `running` record on an OS where it cannot check.

3. **[serious] A job directory whose consumer is in neither `next.Working` nor `next.Final`, or is `working` at another epoch, is never retired, and blocks that consumer id for as long as that holds.** `edge/worker/recover.go:62-76` acts only on ids in the two lists: an id in `next.Final` is retired (`recover.go:63-65`, `finalJob_internal`), a `working` one at a lower gen of the same epoch is retired (`:68-69`); a directory of an id in neither list (a cleared sprint's consumer that the next epoch has not dealt, or one that left the row's `next`) is touched by nothing, and one whose id the new epoch has dealt to this row (epochs reuse consumer ids, doc w4W) is kept as `identity-mismatch-kept` (`recover.go:70-71`: the epoch differs, so `sameEpoch_internal` at `retire.go:162-164` blocks the stale-gen retire). In the second case `pass.go:216` skips the card because the directory exists ("One with a job on disk is recovery's"), so it sits `working` with no process, never faulted, never released, until policy withdraws it, and then is dealt here again; the directory stays until a `next` read lists the id as final, which the new epoch's card does only after that withdrawal. The doc says only "An epoch mismatch is still kept" (w4W, Retire). Repair: retire (nothing pushed) every record whose `Epoch < next.Epoch`, and every record whose consumer is in neither list after one full read, and say so in the doc.

4. **[serious] A PR GitHub merged but whose merge commit could not be read is answered `merge_refused`, with base already moved.** `edge/forge/forge.go:443-449`: `gh pr merge` succeeded, then `gh pr view` fails (a rate limit, a timeout: the 30 s `gh` bound, or the token bucket at `forge.go:205`) and `Merge` returns an error; `edge/git/land.go:223-226` turns every error from `Merge` into `OutcomeRefused` "GitHub refused the merge". Layer 3 opens a land judgement saying refused while base holds the merge; the coordinator's `land` answer then tries to merge a merged PR. With the merge-commit method the next pass heals it (`land.go:85-90`, all heads ancestors); with squash or rebase (defect 5) it never does and the group is rebuilt with heads whose changes are already on base. `LandEdge.tla:128-129` has `merge_refused` leave base `UNCHANGED`, so the model does not have this state. Repair: a typed `MergedUnread` error from `Merge` (the merge call returned 0) that `LandPass` answers as `base_moved` (asked again: the next pass reads base and finds the heads on it) rather than `merge_refused`.

5. **[serious] Under a squash or rebase merge method the landed heads are never ancestors of base, which the doc's step 7 and the next pass assume; nothing checks ancestry after a merge.** `edge/forge/forge.go:481-490` picks merge, then squash, then rebase (LANDING.md:31 allows it). `land.go:85-90` decides "already landed" by `IsAncestor(head, baseTip)`; `land.go:228` records `LandedHeads` as the request's heads. The doc's git-edge step 7 "each landed head is checked an ancestor of the pushed base tip (LPM M21)" exists nowhere in `edge/git` (no `IsAncestor` after `Merge`), and guarantee 4 "Base advances only to a sha whose checks passed at that exact sha" is kept only at the tree level even for the merge-commit method (the merge commit is a new sha). Consequence with squash: any later pass or verb that asks whether a head is on base says no (a retry answer after a judgement, defect 4's re-pass, a re-issued request), and the group branch is rebuilt by merging already-applied heads. Repair: decide at `stream add` (refuse a repository whose allowed methods exclude the merge commit, naming the setting), or make "on base" a tree comparison (`TreeHash`, which exists and is unread) and state guarantee 4 as the tree; either way implement step 7 or delete it from the doc.

## Model vs code

- `Runner.tla:243-252` `Stop` moves only a `running` job (to `staged`); `Rebase`, `Conflict` and `Push` (`:139-164`) are atomic, so the model has no stop inside the rebase-and-test step. The code's stop there writes an outcome (defect 1). `StopIsNeverAFault` (`:402-405`) therefore passes on the model while the code breaks it. Repair: a `Stopping` guard in `Rebase`/`Conflict` (a stop mid-step keeps `harvested` and `outcome = "ok"`), and a reversed witness `RunnerStopDuringRebaseIsAFail`.
- `Runner.tla:289-293` `Restart` keeps `harnessAlive` ("adopt live harnesses by pid and nonce, never spawn a second"): the model assumes `Alive` is truthful; on darwin it is not (defect 2). The witness `RunnerRestartSpawnsSecondHarness` is the shape; the code reaches it on every Mac bench.
- The model has no epoch: the orphan directory of an earlier epoch (defect 3) is outside it; the doc's w4W says epochs reuse ids. `Runner.tla` also has no refused report and no quarantine (the doc admits it, Stitch row 20).
- `LandEdge.tla:124-132`: a green gate either lands, is `merge_refused` with base `UNCHANGED`, or base moves and the pass is asked again. The code can answer `merge_refused` with base moved (defect 4): a state the model does not have, and `Answer(c, "land")` then takes `c \notin Tip.cards` and appends, where the code's hand landing would be refused by GitHub (the PR is merged).
- `LandEdge.tla` has no merge method; `NothingLandsUnpassed` compares trees (`base[i].tree = base[i].gated`), which squash keeps; the code's "on base" is ancestry (`land.go:85-90`), which squash breaks (defect 5). The model is right and the code's predicate is the wrong one.
