# Tool score: nova-sprint v2, by rowan (sonnet, pro tier), card v2r-score-pro1.w8

## Score: 7/10

Good enough that I finished this card from the brief and the CLI alone, not yet a 10 because the first minute is noisy and the contracts a cold AI must trust are spread over too many places.

I was dealt this card, read its brief, cloned the base, and reached `finish` without a human, and every refusal I provoked (`finish` with no args, an unknown verb, `next` with no credential) was one line, named the fix, and exited non-zero. That is the hard part and it works. What holds it below 10: (a) the "stand-alone" brief tells me to read a `JOB.md` and run `go run ./cmd/nova-sprint help`, but the thing I actually had was a recipe file and an `ns` wrapper, so the documented path and the real path differ; (b) `ns show` and `ns finish` print a `SECRETS EXEC STARTING ...` line the recipe has to grep away, and `show` dumps the whole brief twice (once as `brief`, once as `prose`) which costs about 3k tokens of pure duplication; (c) `help` is one 60-line wall where each verb's description is a paragraph (`check`, `add`, `stream add` run to hundreds of characters), so the index does not index; (d) docs/SETUP.md is a contract ("this page becomes the walkthrough an AI runs"), not a walkthrough, and shows no throwaway-store recipe, so I could not safely try the coordinator verbs; (e) the worker playbook is 23 KB and the coordinator's 30 KB, delivered in full by `hook`.

## What is good

1. Refusals are uniform and actionable: `SPRINT REFUSED finish: finish takes <card>@<gen> --head <sha> --as <row> ...: nova-sprint help finish`, and `NEXT this process has no sprint credential` followed by `next: run under nova-secrets exec --only NOVA_SPRINT_PG_PASSWORD,NOVA_BUS_PASSWORD -- nova-sprint ...`. Exit 0/1/2 meaning is stated on line 2 of `help`.
2. `help <verb>` has the same four-line shape for every verb (who, up, "refuses when (and the fix it names)", next). `help finish` lists every refusal with its fix; I never had to read source.
3. Every output ends with a `next:` line, so an AI never has to decide what to do after a verb.
4. docs/PLAYBOOK-WORKER.md "Work a card" is a numbered recipe that matches what I did (take, clone, branch from base, PATHS, commit identity, finish), and "The refusals you will meet" maps each refusal to its action. The `release` / `finish --failed` / `report --result fault` split is the right set of honest exits, and the rule that a fault spends no attempt is stated.
5. Commit identity is enforced by the tool (`finish` refuses a head with a foreign author) and the repair command (`git rebase <base> --exec 'git commit --amend --no-edit --reset-author'`) is printed. That removes a whole class of silent mistakes.
6. The card brief form (tier, PATHS, TEST, DONE-WHEN, NEEDS) is machine-checkable: this card's DONE-WHEN is a single `sh -c` I could run before finishing, and PATHS told me the one file I may change.
7. `finish --head <sha>` is checked against origin, not trusted; "push first: git push origin <branch>" is the refusal I would have met if I forgot.

## What gets it to 10

1. **`show <card>` prints the brief once.** In the JSON, `brief` and `prose` carry the same text (about 3 KB each for this card). Drop `prose` (or `brief`) from `nova-sprint show <card>` output; add `--full` if both are wanted. Done when `ns show <card> | wc -c` is under half of today's for a card with a long brief, and the dashboard and `take` still render the brief.
2. **Remove the `SECRETS EXEC STARTING as=... keys=... cmd=env` line from stdout.** It comes from the `ns` wrapper / nova-secrets exec and every recipe has to `grep -v` it. Send it to stderr, or print nothing when `--quiet`. Done when `ns show X | head -1` is `{` and no recipe contains `grep -v "SECRETS EXEC"`.
3. **Make `finish` discoverable without the generation dance.** Recipes compute `gen` with `show | grep -o '"gen"...'` before `finish <card>@<gen>`. Let `finish <card> --head ...` (and `take`) accept an omitted `@gen` for a card held by `--as` and resolve it, still refusing if the row holds none; or make `show --gen <card>` print just the number. Done when the recipe's finish step is a single line with no grep.
4. **Print the live job's identity at the top of the worker's view.** The brief says read `JOB.md`, but a worker started by hand has no `JOB.md` and no `take` output until it runs `take`. Make `ns next --as <row>` print, for a card in hand, the exact `take` line, the repository, the branch and the base sha in a fixed 4-line header, and have docs/PLAYBOOK-WORKER.md "Work a card" step 1 start from that. Done when a cold AI handed only `next`'s output can clone, branch and finish with no other file.
5. **Shrink `help` to an index.** Cap each verb's line in `nova-sprint help` at about 100 characters (move the `check` and `stream add` paragraphs into `help check` / `help stream add`). Done when `nova-sprint help | wc -c` is under 3 KB and `help <verb>` still carries the full text.
6. **Split the playbooks by moment, not by role.** `hook` prints 23 KB (worker) or 30 KB (coordinator) up front. Print a 40-line "first card" card (hook, take, clone, finish, the three exits) and make the long text `help playbook worker --section <name>` (`refusals`, `read`, `stuck`). Done when `hook --role worker` output is under 4 KB and every section name appears in the one-line refusals.
7. **Give SETUP.md a runnable section.** Add "Try it on a throwaway store": the exact `nova-secrets exec ... nova-sprint up --as <you>` against a scratch PostgreSQL database, the environment variable or flag that points at it, and the teardown (`clear`). Done when a cold AI can run `up`, `stream add`, `add`, `next`, `show`, `queue` on the scratch store from the page alone and `check` prints no CHECK RED line, and the page states plainly that no verb touches the live store without `--store`/the variable.
8. **Make the contract pages say "status" first.** docs/README.md layer entries are long history of lock rounds ("Re-locked 2026-11-06 at 1894ced3 after rounds 13 to 16..."). Put one line per layer: state, entry point, the doc to read for a worker. Done when README.md's layer list is under 25 lines and the lock history lives in each LAYER-*.md.
9. **Add `nova-sprint doctor --as <row>` output to `next` when it cannot run.** Today `next` without a credential tells me to use `nova-secrets exec --only ...`; make that line a complete, copy-pasteable command including the binary path, and add a worker-side `check --worker` that tests only what a worker needs (bus, store read, git identity, forge reachable) in under a second. Done when a worker with a missing piece gets exactly one `check --worker` line naming it.
10. **Report cost without the guess.** `finish --cost <usd>` makes an AI estimate its own spend; the recipe passes `--cost 0`. Let the harness supply it (the `report --cost-microusd --priced` form already exists) and have `finish` print `cost not reported` instead of silently taking 0. Done when a card finished without `--cost` shows `priced:false` on the board, not 0.

Three entry paths for one moment. Files: docs/PLAYBOOK-WORKER.md "Work a card" step 1, docs/LAYER-4-EDGES.md "JOB.md (68)", `ns show`.

I cannot tell which of `ns`, `nova-sprint` and `nova-secrets exec` is the supported way, nor whether it touches the live store. Verb: `next`, `check`; page: docs/SETUP.md (silent on this).

2. `nova-sprint help` plus ten `help <verb>` calls to find the refusals: about 4k tokens, most of it the paragraph-long index lines and the identical `up:` line repeated on every verb.
3. The two playbooks (53 KB) and CORRECT-USE (18 KB) are mostly for the coordinator and for history; a worker on a review card needs about 5 KB of them. Reading headings first, then one section, was the only affordable path and the page does not say which sections a worker can skip.
4. Building the binary (`go build ./cmd/nova-sprint`) and cloning with `--filter=blob:none` were cheap (seconds); the cost of this card was reading, not running.
