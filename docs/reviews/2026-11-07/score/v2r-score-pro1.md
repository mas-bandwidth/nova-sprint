## Score: 7/10

I am the AI using nova-sprint right now: I was dealt this card by it, I read the JOB.md, and I will finish with its verb. The tool's core is genuinely written for an agent, not for a human pretending to be one. `nova-sprint help` is a grouped index; `help <verb>` is the same four-field contract for every one of the 30+ verbs (`who` / `up` / `refuses when` / `next`); every refusal I hit was one line naming the one command that fixes it; the tool enforces hook-order, a single commit identity, and DONE-WHEN-as-one-argv so no model has to remember a rule. That is the hardest part of "good for AIs" and it is largely done. It is not a 10 because the cold-start promise the project itself sets — "an AI with no memory takes a fresh fleet from zero to a running sprint using only docs/README.md and the tool's own help" (SETUP 4) — is not true for a lone AI today. The card I was given does not carry the work (my JOB.md has kind/repo/base/checkout/paths/done-when but not the task prose, TEST, or deliverable), there is no documented way to rehearse any acting verb against a throwaway store, and this very review card's done-when gate checks only two of the five sections the grading rubric requires. When the card is self-contained and a cold AI can run the verbs safely before touching a live fleet, this is a 10.

## What is good

- **`help <verb>` is a uniform contract, verb by verb (verbs/help.go).** I ran `help`, then `help` for every verb individually. Every table is the same four lines a cold AI needs: `who:` (who may run it), `up:` (what must exist first), `refuses when` (each refusal names its one fix), and a closing `next:` line. `help version` even ends `next: nova-sprint version`. This is the single best artifact in the tool.
- **Refusals are one line, name the fix, and use honest exit codes (CORRECT-USE "The one rule").** Running `check` cold gave `CHECK RED` lines each naming its own fix, then `SPRINT REFUSED check: 3 lines are red; the first: ...` with exit 1. `take` cold refused with the exact fix (`nova-sprint check`). The `SPRINT REFUSED <verb>: <not true>: <fix>` shape held on every verb I tried, including the "no sprint credential" case.
- **Exit codes are meaningful.** `version` and `next` cold exit 0; a refusal exits 1; the store/bus/edge failures exit 2. The help text for every verb documents the exit semantics, and a cold AI can script on them.
- **The deal message, receipts, and `next` are self-carrying.** Every output ends `next: <command>`, and the playbook's "write run everything in your hand" rule makes the loop explicit (PLAYBOOK-WORKER 22-30). `take` prints the full brief and the finish command; nothing has to live in model memory.
- **Enforcement lives in the tool, not the model.** Hook-before-acting, the single git identity with author-email checks on `finish`, DONE-WHEN-as-one-argv, and the one-chooser lock are all refused by name (CORRECT-USE; LAYER-6). This is the right split between "tool" and "AI".
- **The project states its own cold-start bar and is honest about what is owed.** The dogfood gate is explicit (SETUP 4), README tracks the release gates, and CORRECT-USE lists what is Built vs. still owed. That honesty is rare and useful.

## Where I would be lost cold

1. **Fresh machine, no fleet: every useful verb refuses at the fleet or the store, and the recovery is another whole toolchain.** `next` and `check` correctly point me at `nova-fleet` and credentials, but stepping from "no tools" to a running store requires Tailscale, Redis, PostgreSQL, Ansible, and a human's key pastes — setup the docs assume rather than let a lone AI complete unattended. Gate 2 of SETUP 4 exists but is not demonstrated, so I am lost before the first verb that does anything.
2. **The card file does not carry the work.** My JOB.md holds kind, repository, base, checkout, `paths`, and `done-when` — but not the task prose, the TEST, or the deliverable description. That text reached me only through the deal/prompt, not the job directory. A harness that opens the job directory alone cannot learn what to build; I had to import context from outside the card.
3. **There is no sandbox, so I cannot rehearse.** The only verbs I can run cold are `help`, `version`, `next` (which refuses), and `check` (which refuses red). To learn the real shapes of `take`/`finish`/`read`/`up`/`stream add`/`add` I would need a live sprint or a fleet I do not have; the only `--dry-run` flags are on coordinator verbs. I judged the tool without once running an acting verb.

## Tokens and time

- **Biggest cost: reading the operator docs to separate what I must do from design history.** PLAYBOOK-WORKER (312 lines), PLAYBOOK-COORDINATOR (417), CORRECT-USE (287), README (223), and LAYER-6 (906) restate the same refusals, prerequisite chain, and rules several times. I spent most of my budget distinguishing "what a worker must run" from "how the layer is built". A short minimum-reading path (item 4) would have saved the most.

- Compiling and running `version`/`next`/`check`/`help` was quick and truthful; the tool's feedback loop is fast and reassuring. `go build`/`go run` needed a Go toolchain not on the default PATH (found at `/home/nova/sdk/go1.26.6/bin`), a one-line environment fix.
