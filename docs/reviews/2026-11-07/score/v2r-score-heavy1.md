# nova-sprint v2: the tool score from the AI that was dealt this card

## Score: 7/10

Seven because the in-sprint loop is genuinely strong: the help index finds the right verb, every verb's table names its prerequisites and fixes, refusals are one line with an exit code, `check` is a real doctor, and the worker playbook is a push-driven walkthrough with the next command on every message. I was dealt this card by the tool and could take, read and finish it without a human. It is not a 10 because the cold path is still a contract rather than a tool: `docs/SETUP.md` is not the walkthrough it says it will become, there is no documented throwaway store, `help <verb>` ends in placeholders (`next: nova-sprint add ...`), a cold `nova-sprint` sends an AI to `nova-secrets exec` instead of `check`/`up`, and coordinator onboarding prints 731 lines with the worker's 313 lines first. An AI that already lives in a sprint is well served; an AI meeting the tool from a fresh clone is still asked to read the design history to find the start.

## What is good

- **The help index is a real map.** `verbs/help.go:58` groups every verb under `start`, `work`, `coordinate` and `operate`, and each line says the role and whether the verb is cold; `nova-sprint help` printed every verb without me opening the source. That is exactly the right first screen.
- **Each verb's table is uniform and actionable.** `verbs/help.go:83` (`helpVerb`) prints usage, one-sentence purpose, `who:`, `up:`, the refusal/fix pairs, then `next:`. `nova-sprint help finish` names the actual fix for the common failure: `not on the dealt branch at origin: git push origin <branch>`. I never had to guess who owns a verb or what it needs first.
- **Refusals obey one grammar and one exit convention.** `docs/CORRECT-USE.md:15-20` promises `SPRINT REFUSED <verb>: <what is not true>: <the command that makes it true>`; the binary does it. Observed: `SPRINT REFUSED nova-sprint: unknown verb frobnicate: nova-sprint help` (exit 2), and `SPRINT REFUSED show: no name given: pass --as <you>, or set NOVA_SPRINT_AS=<you>` (exit 1). `verbs/result.go:15` documents the 0/1/2 split, so a harness can branch without parsing prose.
- **`check` is the doctor an AI needs.** `docs/CORRECT-USE.md:174-222` and `verbs/check_test.go:41-62` show a line per thing checked, a fix on each `CHECK RED`, non-zero exit while any is red, and an honest caveat: a job dead on a healthy bench is not visible because no per-job heartbeat reaches the store. On this bench `check` printed the fleet, pin, credential, bus and first red fix in the first five lines, which is the right ordering for a cold AI.
- **The worker playbook is push-first, not poll-first.** `docs/PLAYBOOK-WORKER.md:44-50` says every deal, read ask, withdraw and landing reaches you as one bus message carrying the command that answers it; `docs/PLAYBOOK-WORKER.md:99-129` lists the message forms and the exact `take`/`finish`/`read` line. This is the part that makes the tool usable unattended.
- **The finish/read loop is checked, not trusted.** `docs/CORRECT-USE.md:106-119` and `docs/PLAYBOOK-WORKER.md:131-190,213-238` make the head, branch, commit identity and read findings part of the verb, not a convention. `verbs/work_test.go:98,142` pin `FINISHED ... --head` and `READ ... result=fix`, so an AI sees a receipt rather than a silent success.
- **`JOB.md` is enough to work a card.** `edge/worker/jobmd.go:21-78` writes the consumer, kind, tier, repo, base, branch/checkout, paths, done-when, the prose and the exact `result.json` forms; the `JOB.md` I was given also carried the branch, base, paths, done-when and finish rule. A cold child can start from that file alone.
- **The implementation is testable and green in the unit tier.** `go test ./verbs ./docs` passed here, and the tests pin the help/refusal/take/finish receipts rather than only prose.

## What gets it to 10

1. **Turn `docs/SETUP.md` from a contract into the walkthrough it promises.** `docs/SETUP.md:1-4` still says "This is what the setup must be; layer 6 makes it exact and this page becomes the walkthrough an AI runs," but sections 1-5 are requirements prose. Replace it with numbered commands and expected first lines: `nova-fleet check`, `nova-sprint check`, `nova-sprint up --as <you> --dash ... --services ...`, `nova-sprint stream add`, `nova-sprint add --dry-run`, `nova-sprint start`, each with the one failure branch an AI will meet. Done when a fresh AI with only `README.md` and `nova-sprint help` can follow the page top to bottom on a fresh fleet, twice, without opening `docs/LAYER-6-RUN.md`.

2. **Expose a documented throwaway store.** `docs/LAYER-6-RUN.md:589` names `run/filestore` as a manual-test seam, but no user-facing verb and no SETUP section reaches it; `docs/SETUP.md` only describes the real fleet, so I could not safely try `add`, `hook`, `take` or `finish` without touching a live store. Add a `nova-sprint up --dev` (or a `make dev-up` recipe documented in SETUP) that creates a local PostgreSQL/Redis or the file store and sets `NOVA_PG_DSN`/`NOVA_BUS_REDIS`, plus the cleanup command. Done when an AI can run a full throwaway `stream add` -> `add --dry-run` -> `hook` -> `take` -> `finish` loop with no production credentials, and `check` is green on that store.

3. **Add a build-and-first-command block to `README.md`.** `README.md:20` says only "ask your AI to read the docs"; it has no Go version, no `make build`, no first command, and on this bench `go` was not on `PATH` (the toolchain was at `/home/nova/sdk/go1.26.6/bin/go`). Put five lines after the banner: the Go version, the nova-tools prerequisite, `make build`, `./bin/nova-sprint help`, `./bin/nova-sprint check`. Done when a new AI can go from a fresh clone to `help` without reading `docs/README.md`.

4. **Make every `help <verb>` end with a runnable command.** `verbs/help.go:68` emits `done("nova-sprint "+v.name+" ...", ...)`, so `nova-sprint help add` ends `next: nova-sprint add ...` and `help take` ends `next: nova-sprint take ...`; the placeholder is not copyable and contradicts the `next:` convention. Give each verb one concrete example (or drop the `next:` line), e.g. `help add` -> `nova-sprint add --stream s --brief-file card.md --dry-run`, `help take` -> `nova-sprint take p1.w1@1 --as <you> --epoch <e>`. Add a test in `verbs/help_test.go` that no help output contains `...` in its last line. Done when the test is green and `take`, `finish`, `read`, `next` each print a command a worker can run.

5. **Fix the cold `nova-sprint` path.** With no sprint environment, `nova-sprint` (which is `next`, `verbs/verbs.go:129-132`) prints `NEXT this process has no sprint credential` and `next: run under nova-secrets exec --only ... -- nova-sprint ...`. A truly cold AI has no store and no seat yet, so the first fix is `nova-sprint check`/`nova-sprint up`, not a secrets command. Detect "no store/credential yet" before the credential refusal, or make the no-argument path call `check` first and print `next: nova-sprint check`. Done when a fresh process with no `NOVA_*` prints the setup path instead of the secrets line, pinned in `verbs/fresh_test.go`.

6. **Stop printing both playbooks on coordinator onboarding.** `docs/playbooks.go:16-23` returns `worker + "\n" + coordinator`, so `help playbook coordinator` and `hook --role coordinator` print 313 lines of worker rules before line 314 starts the coordinator's playbook. Return the coordinator playbook alone for `help playbook coordinator`, or print a ten-line index that names `help playbook worker` and `help playbook coordinator`; keep both embedded. Done when the coordinator's first screen names the coordinator's own verbs and the total is under about 420 lines, with a test that the coordinator heading is near the top.

7. **Put one complete, accepted brief in the contract and in `help add`.** `docs/CARD-CONTRACT.md:11-24,106-182` and `nova-sprint help add` list the fields and admission refusals but never show a brief that passes. Add a copyable example with `tier:`, `PATHS:`, `TEST:`, `DONE-WHEN:` and prose to `docs/CARD-CONTRACT.md` and `help add`, plus a golden `add --dry-run` transcript. Done when copying the example to a file and running `nova-sprint add --stream s --brief-file <file> --dry-run` succeeds on a freshly set-up stream.

8. **Update the stale DEAL sample in CORRECT-USE.** `docs/CORRECT-USE.md:93-104` still shows `DEAL card=<id> attempt=<n> kind=work|read stream=<s> epoch=<e>` and `run: nova-sprint take <id>@<gen> --as <you>`, missing the current `tier`, `model`, `repo`, `base`, `branch`, `brief` and the `--epoch <e>` flag that `docs/PLAYBOOK-WORKER.md:107-112` tells a worker to copy. Replace it with the current renderer output, or delete the sample and point at the playbook. Add a test that pins the doc sample to a rendered deal. Done when the sample and a real deal differ only in values.

9. **Make `show` usable exactly as the playbook prints it.** `show` is a worker/coordinator verb (`verbs/look.go:20`) and `nova-sprint show foo` with no actor refuses `no name given`, while `docs/PLAYBOOK-WORKER.md:296` tells a stuck AI to run `nova-sprint show <id>` and the help synopsis is `show [<card>|<stream>|<row>|run]`. Either let the read-only `show` run without an actor (it only reads a snapshot), or add `--as <you>` to the usage and to every playbook example. Done when `nova-sprint show <unknown>` either names the unknown record or the help/playbook line shows the required `--as`.

10. **Put a 50-line "start here" at the top of `docs/README.md`.** `docs/README.md` is 223 lines of layer history and standards before an AI reaches the actual workflow, and its prerequisites at lines 20-23 (Tailscale, Redis, PostgreSQL, Ansible) read as a wall. Add a short block at the top: `nova-sprint help`, `nova-sprint check`, `nova-sprint up`, then the worker and coordinator playbook links and the `SETUP.md` walkthrough. Done when the first screen answers "what is this, what do I run first, where is the card contract" without scrolling.

## Where I would be lost cold

1. **At setup, in `docs/SETUP.md`.** The first four lines say this is the contract, not the walkthrough; the rest describes what `up` must do. `docs/README.md:20-23` says Tailscale, Redis, PostgreSQL and Ansible are required, then moves into layer history. With no local option and no exact command sequence, a new AI does not know whether to run `nova-fleet`, `nova-sprint up`, or `nova-sprint check` first, and cannot try a verb without a live fleet.

2. **At the coordinator's first screen, in `help playbook coordinator` / `nova-sprint hook --role coordinator`.** `docs/playbooks.go:16-23` prints the worker playbook first, so line 1 is `# The worker's playbook` and the coordinator's own rules start at line 314. For 313 lines the new coordinator is told to take, finish and read cards before it learns that it is the one name that answers judgements, sets priorities and changes policy. That is a long time holding the wrong mental model.

3. **At the first card, in `nova-sprint help add` and `docs/CARD-CONTRACT.md`.** The help says admission will refuse "a brief missing a contract section, by name," and the contract explains every field, but neither shows a complete brief that passes. The only prose template is split across `docs/PLAYBOOK-COORDINATOR.md:197-217` and `docs/CARD-CONTRACT.md:11-24,106-182`; a cold coordinator has to synthesize the format and discover `TEST:`/`DONE-WHEN:` command-vs-shell rules from the refusal. One copyable example would remove the stall.

## Tokens and time

The most expensive thing was not a verb; it was the absence of a 50-line start-here. I read `docs/README.md` (223 lines), `docs/PLAYBOOK-WORKER.md` (312), `docs/PLAYBOOK-COORDINATOR.md` (417), `docs/CARD-CONTRACT.md` (181), `docs/CORRECT-USE.md` (287) and `docs/SETUP.md` (90) before I had the whole loop, then ran `help` for all 40 verb pages. `help playbook coordinator` alone is 731 lines because of the worker+coordinator concatenation, and every verb page repeats the same `who:`/`up:`/`next: ...` boilerplate. The second cost was that half the walk had to be reading rather than doing: `docs/SETUP.md` has no throwaway-store recipe, so `add`, `hook`, `take`, `finish` and `read` could not be tried safely, and `go run` recompiled on every call because `go` was not on `PATH`. The third cost was cross-checking: the DEAL sample in `docs/CORRECT-USE.md` and the help `next: ...` placeholders look authoritative but do not match the commands the playbook tells you to copy, so each contradiction sends an AI back to the source or the tests.
