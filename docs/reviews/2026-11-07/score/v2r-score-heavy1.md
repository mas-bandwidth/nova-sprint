# nova-sprint v2: scored by the AI it dealt this card to

## Score: 7/10

Seven because once I am inside a sprint the tool is genuinely good to work: the help index is a map of every verb and its role, each verb table has the same `who:`/`up:`/refusal/`next:` shape, refusals are one line with an exit code and a repair command, `check` is a real doctor, and the worker playbook is a push-driven walkthrough whose every message carries the command that answers it. I was dealt this card by nova-sprint, read `JOB.md`, built the binary, ran `help`, `check`, `help <verb>` for every verb, and wrote this file without a human. It is not a 10 because the cold path is still a design contract rather than a tool: `docs/SETUP.md` explicitly says it is not the walkthrough, there is no documented throwaway store so I could not safely try `add`, `take`, `finish` or `read`, `README.md` has no build or first command, every `help <verb>` ends in an uncopyable `...`, the coordinator playbook opens with 313 lines of the worker playbook, and the coordinator is still told to run an `edit` verb that the binary refuses. An AI already living in a sprint is well served; an AI meeting nova-sprint from a fresh clone is still sent into the layer history to find the front door.

## What is good

- **The help index is a map, not a wall.** `verbs/help.go:41` (`helpIndex`) groups every verb under `start`, `work`, `coordinate` and `operate`, labels each with its role and whether it is cold, and ends with the next command. `nova-sprint help` printed all 40 verbs without my opening the source. That is the right first screen.
- **Every verb table has one shape.** `verbs/help.go:60` (`helpVerb`) prints usage, a one-sentence purpose, `who:`, `up:`, a refusal/fix list, then `next:`. `nova-sprint help finish` names the actual common repair, `not on the dealt branch at origin: git push origin <branch>`, so I never had to infer ownership or prerequisites from prose.
- **Refusals obey one grammar and one exit convention.** `verbs/result.go:15-38` defines 0 done / 1 refused / 2 could not run, and `docs/CORRECT-USE.md:15-20` promises `SPRINT REFUSED <verb>: <what is not true>: <the command that makes it true>`. I saw `SPRINT REFUSED nova-sprint: unknown verb frobnicate: nova-sprint help` (exit 2) and `SPRINT REFUSED queue: no name given: pass --as <you>, or set NOVA_SPRINT_AS=<you>` (exit 1). A harness can branch on that without parsing prose.
- **`check` is the doctor an AI needs.** `verbs/check.go` and `verbs/check_test.go` print one line per fact and a fix beside each red line. On this bench it led with `nova-fleet check` (missing `ansible-playbook` and `TAILSCALE_API_KEY`), the nova-tools pin, the missing sprint credential and the missing bus address, then refused with the first fix. `docs/CORRECT-USE.md:174-222` is also honest that a job dead on a healthy bench is invisible because no per-job heartbeat reaches the store.
- **The worker playbook is push-first, not poll-first.** `docs/PLAYBOOK-WORKER.md:44-50` says every deal, read ask, withdraw and landing arrives as one bus message carrying the command that answers it; lines 99-129 give the exact deal, nudge, withdraw and finish forms. That is what makes the tool usable unattended.
- **The take/finish/read loop is checked, not trusted.** `docs/PLAYBOOK-WORKER.md:131-190,213-238` makes the head, branch, commit identity and read finding part of the verb, and `verbs/work_test.go:98,142` pin the `FINISHED ... --head` and `READ ... result=fix` receipts. I would see a receipt rather than a silent success.
- **`JOB.md` is enough to work a card.** `edge/worker/jobmd.go:21-78` writes the consumer, kind, tier, repo, base, branch/checkout, paths, done-when, the prose and the exact `result.json` forms. The `JOB.md` I was given carried all of it, so a cold child can start from that one file.
- **The card contract is unusually precise.** `docs/CARD-CONTRACT.md:106-151` names every admission check, including the one-argv `DONE-WHEN` rule and the `sh -c '...'` escape hatch. This is the kind of refusal an AI can act on without a human.
- **The unit tier is green and pins behaviour.** `go test ./verbs` passed here, and the tests assert help, refusal, take, finish and empty-brief receipts rather than only prose.

## What gets it to 10

1. **Turn `docs/SETUP.md` from a contract into the walkthrough it promises.** `docs/SETUP.md:1-4` still says "This is what the setup must be; layer 6 makes it exact and this page becomes the walkthrough an AI runs," but sections 1-5 are requirements prose with no commands. Replace it with numbered commands and the expected first line for each: `nova-fleet check`, `nova-sprint check`, `nova-sprint up --as <you> ...`, `nova-sprint stream add`, `nova-sprint add --dry-run`, `nova-sprint start`, each with the one failure branch an AI will meet. Done when a fresh AI with only `README.md` and `nova-sprint help` can go top to bottom on a fresh fleet twice without opening `docs/LAYER-6-RUN.md`.

2. **Expose a documented throwaway store.** `docs/LAYER-6-RUN.md:589` names `run/filestore` as a manual-test seam, but no user-facing verb and no SETUP section reaches it; the only documented target is the live fleet, so I could not safely try `add`, `hook`, `take`, `finish` or `read`. Add a `nova-sprint up --dev` (or a `make dev-up` recipe in SETUP) that creates a local PostgreSQL/Redis or the file store and sets `NOVA_PG_DSN`/`NOVA_BUS_REDIS`, plus its cleanup command. Done when an AI can run `stream add` -> `add --dry-run` -> `hook` -> `take` -> `finish` with no production credentials and `check` is green on that store.

3. **Add a build-and-first-command block to `README.md`.** `README.md:20` says only "ask your AI to read the docs"; it has no Go version, no `make build`, no first command, and on this bench `go` was not on `PATH` (the toolchain was at `/home/nova/sdk/go1.26.6/bin/go`). Put five lines after the banner: the Go version, the nova-tools prerequisite, `make build`, `./bin/nova-sprint help`, `./bin/nova-sprint check`. Done when a new AI can go from a fresh clone to `help` without opening `docs/README.md`.

4. **Make every `help <verb>` end with a runnable command.** All verb pages do `done("nova-sprint "+v.name+" ...")` at `verbs/help.go:68`, so `help add` ends `next: nova-sprint add ...`, `help take` ends `next: nova-sprint take ...`, and `help version` ends in a no-op loop. Add one concrete example per verb, or drop the `next:` line where nothing follows, for example `help add` -> `nova-sprint add --stream s --brief-file card.md --dry-run`. Add a test in `verbs/help_test.go` that no help page's last line contains `...`. Done when `take`, `finish`, `read`, `add`, `stream add` and `next` each print a copyable command.

5. **Fix the cold `next`/no-argument path.** `nova-sprint next` with no sprint environment prints `NEXT this process has no sprint credential` and `next: run under nova-secrets exec --only ... -- nova-sprint ...` (from `verbs/result.go:52-55` and `verbs/next.go:108-130`), even though a truly cold AI has no store and no seat. `docs/CORRECT-USE.md:29` says the no-argument path is the cold AI's front door, so that front door must lead to `nova-sprint check` or `nova-sprint up`, not to a secrets command. Detect "no store/credential yet" before the credential guidance, or make the bare command run `check` first. Done when a fresh process with no `NOVA_*` prints `next: nova-sprint check` (or `up`) and a test pins it in `verbs/fresh_test.go`.

6. **Stop printing both playbooks on coordinator onboarding.** `docs/playbooks.go:13-19` returns `worker + "\n" + coordinator`, so `help playbook coordinator` and `hook --role coordinator` print 731 lines and the coordinator heading is at line 314. A new coordinator holds the worker's mental model for 313 lines before hearing that it is the one that answers judgements, sets priorities and changes policy. Return the coordinator playbook alone for `help playbook coordinator`, or print a ten-line index naming both roles. Done when the coordinator heading is near the top and a test asserts it.

7. **Remove the ghost `edit` verb, or build it.** `docs/PLAYBOOK-COORDINATOR.md:14` lists "edit ... a card" as a coordinator power and line 293 says "fix the brief with `edit` before another attempt," but the verb table has no `edit`: `nova-sprint help edit` gives `SPRINT REFUSED help: no verb edit: nova-sprint help help` and `verbs/core_test.go` pins `edit` as an unknown verb. Either add the documented card-edit verb with its refusals and tests, or change both lines to the real recovery (`drop` + `add` a corrected brief). Done when neither playbook contains a command the binary refuses, and a test fails if a backticked `nova-sprint <verb>` in either playbook is not in the table.

8. **Put one complete, accepted brief in the contract and in `help add`.** `docs/CARD-CONTRACT.md:11-24,106-182` and `nova-sprint help add` list the fields and the admission refusals but never show a brief that passes. The only collection is prose split across `docs/PLAYBOOK-COORDINATOR.md:197-217` and the contract. Add a copyable example with `tier:`, `PATHS:`, `TEST:`, `DONE-WHEN:` and prose to both, plus a golden `add --dry-run` transcript. Done when copying the example to a file and running `nova-sprint add --stream s --brief-file <file> --dry-run` succeeds on a freshly set-up stream.

9. **Update the stale DEAL sample in CORRECT-USE.** `docs/CORRECT-USE.md:96-97` still shows `DEAL card=<id> attempt=<n> kind=work|read stream=<s> epoch=<e>` and `run: nova-sprint take <id>@<gen> --as <you>`, missing the current `tier`, `model`, `repo`, `base`, `branch`, `brief` and the `--epoch <e>` flag that `docs/PLAYBOOK-WORKER.md:107-112` tells a worker to copy. Replace it with the current renderer output, or delete the sample and point at the playbook. Add a test that pins the doc sample to a rendered deal. Done when the sample and a real deal differ only in values.

10. **Make `show` usable exactly as the playbooks print it.** `verbs/table.go:126` makes `show` a worker/coordinator verb, so `nova-sprint show foo` with no actor refuses `no name given`, while `docs/PLAYBOOK-WORKER.md:287,296` and `docs/PLAYBOOK-COORDINATOR.md:96,140,148,295,409` tell a stuck AI to run `nova-sprint show <id>`. The synopsis `[<card>|<stream>|<row>|run]` never mentions `--as`, and `show` only reads a snapshot. Either let the read-only `show` run without an actor, or add `--as <you>` to the usage and every playbook example. Done when `nova-sprint show <unknown>` either names the unknown record or the help/playbook line shows the required `--as`.

11. **Correct the worker playbook's credential claim.** `docs/PLAYBOOK-WORKER.md:82` says "Every nova-sprint verb needs the sprint's credential in its process," but `verbs/help.go:44` says `help`, `version`, `up` and `check` run anywhere. A cold AI will wrap `check` in `nova-secrets exec` unnecessarily, or believe it cannot inspect the bench. Change the playbook sentence to name the exception, and add the same sentence to `help`'s index. Done when `help`, `version`, `check` and `up` are explicitly listed as credential-free in both places.

12. **Put a 50-line "start here" at the top of `docs/README.md`.** `docs/README.md` is 223 lines of layer history and standards before the actual workflow, and its prerequisite sentence at lines 20-23 (Tailscale, Redis, PostgreSQL, Ansible) reads as a wall. Add a short block at the top: `nova-sprint help`, `nova-sprint check`, `nova-sprint up`, then the worker and coordinator playbook links and the `SETUP.md` walkthrough. Done when the first screen answers "what is this, what do I run first, where is the card contract" without scrolling.

## Where I would be lost cold

1. **At setup, in `docs/SETUP.md`.** The first four lines say this is the contract, not the walkthrough; the rest describes what `up` must do. `docs/README.md:20-23` says Tailscale, Redis, PostgreSQL and Ansible are required, then moves into layer history. With no local option and no exact command sequence, a new AI does not know whether to run `nova-fleet`, `nova-sprint up` or `nova-sprint check` first, and cannot try a verb without a live fleet.

2. **At the coordinator's first screen, in `help playbook coordinator` / `nova-sprint hook --role coordinator`.** `docs/playbooks.go:13-19` prints the worker playbook first, so line 1 is `# The worker's playbook` and the coordinator's own rules start at line 314 of 731. For 313 lines the new coordinator is told to take, finish and read cards before it learns that it is the one name that answers judgements, sets priorities and changes policy.

3. **At the first card, in `nova-sprint help add` and `docs/CARD-CONTRACT.md`.** The help says admission will refuse "a brief missing a contract section, by name," and the contract explains every field, but neither shows a complete brief that passes. The only prose template is split across `docs/PLAYBOOK-COORDINATOR.md:197-217` and `docs/CARD-CONTRACT.md:11-24,106-182`; a cold coordinator has to synthesize the format and discover the `TEST:`/`DONE-WHEN:` command-versus-shell rules from the refusal. One copyable example would remove the stall.

## Tokens and time

The most expensive thing was not a verb; it was the absence of a 50-line start-here. I read `docs/README.md` (223 lines), `docs/PLAYBOOK-WORKER.md` (312), `docs/PLAYBOOK-COORDINATOR.md` (417), `docs/CARD-CONTRACT.md` (181), `docs/CORRECT-USE.md` (287) and `docs/SETUP.md` (90) before I had the whole loop, then ran `help` for all 40 verb pages. `help playbook coordinator` alone is 731 lines because of the worker+coordinator concatenation, and every verb page repeats the same `who:`/`up:`/`next: ...` boilerplate. The second cost was that half the walk had to be reading rather than doing: `docs/SETUP.md` has no throwaway-store recipe, so `add`, `hook`, `take`, `finish` and `read` could not be tried safely, and `go run` recompiled on every call because `go` was not on `PATH`. The third cost was cross-checking: the DEAL sample in `docs/CORRECT-USE.md`, the `next: ...` placeholders, the ghost `edit` verb, the playbook's `show <id>` and the playbook's "every verb needs the credential" all look authoritative but do not match what the binary accepts, so each contradiction sends an AI back to the source or the tests.
