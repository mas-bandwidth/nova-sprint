# nova-sprint v2, scored cold by the AI it dealt this card to

## Score: 7/10

Seven because the part of the tool that faces an AI with a card in its hand is genuinely good. I was dealt this card by nova-sprint, read `JOB.md`, built the binary with Go 1.26.6, ran `help` and `help <verb>` for all 40 verbs, ran `check`, `next`, `hook`, `up`, `show` and `queue` cold, read both playbooks, the card contract, SETUP and CORRECT-USE, and wrote this file without a human. The help index is a real map, refusals are one line with an exit code and a repair command, `check` is a doctor, `JOB.md` was enough to start the task, and the worker loop is push-driven with every receipt checked. It is not a 10 because the cold path is still a contract written ahead of the product: `README.md` has no build or first command, `docs/SETUP.md` says outright it is not the walkthrough, there is no user-facing throwaway store so I could not safely run `add`, `hook`, `take`, `finish` or `read`, every `help <verb>` page ends in an uncopyable `...`, the bare command prints a `nova-sprint ...` placeholder instead of `check`/`up`, the coordinator's playbook opens with 313 lines of the worker's, and several documents still name a `show`/`edit`/DEAL form the binary does not accept. An AI already inside a sprint is well served; an AI meeting nova-sprint from a fresh clone is still sent into the layer history to find the front door.

## What is good

- **The help index is a map, not a wall.** `verbs/help.go:36-51` groups all 40 verbs under `start`, `work`, `coordinate` and `operate`, labels each with its role and whether it is cold, and ends with the next command. `nova-sprint help` put the whole surface on one screen; I never had to open the source to discover a verb.
- **Refusals obey one grammar and one exit convention.** `verbs/result.go:15-43` defines 0 done / 1 refused / 2 could not run, and every refusal I provoked printed `SPRINT REFUSED <verb>: <what is not true>: <the command that makes it true>`. Real examples: `SPRINT REFUSED queue: no name given: pass --as <you>, or set NOVA_SPRINT_AS=<you>` (exit 1), `SPRINT REFUSED help: no verb frobnicate: nova-sprint help help` (exit 2), `SPRINT REFUSED show: nova-bus who failed ...: nova-sprint check` (exit 2). A harness can branch on that without parsing prose.
- **`check` is the doctor an AI needs.** `verbs/check.go` and `verbs/check_test.go:53-204` print one line per fact with the fix beside the red ones. Cold on this bench it led with `nova-fleet check is not green`, then the nova-tools pin (`v2.0.3 (pin v2.0.3)`), the missing sprint credential, and the missing `NOVA_BUS_REDIS`, then refused with the first fix.
- **`JOB.md` is enough to work a card cold.** `edge/worker/jobmd.go:21-80` writes the consumer, kind, tier, repo, base, checkout, branch, paths, done-when, the prose, the exact commit rule and the two `result.json` forms. The `JOB.md` I was given carried all of it, including the condition under which this card is a work card rather than a read, so a cold child starts from that one file.
- **The worker playbook is push-first.** `docs/PLAYBOOK-WORKER.md:99-129` gives the exact deal, nudge, withdraw, fix and result forms, and line 44-50 says every one arrives as a bus wake carrying the command that answers it. The refusal table at lines 236-282 names the repair for each case I could provoke.
- **The take/finish/read loop is checked, not trusted.** `verbs/work_test.go:20-33,94-98,139-142` pin `TAKEN ...`, `FINISHED <id> head=<sha>`, and `READ ... result=fix`; `docs/PLAYBOOK-WORKER.md:131-190` makes the head, branch, commit identity and fix finding part of the verb. I would see a receipt, not a silent success.
- **The card contract is unusually precise.** `docs/CARD-CONTRACT.md:1-78` names the tier, PATHS, NEEDS, AFTER, PRIORITY, TEST and DONE-WHEN rules, including the one-argv gate and the `sh -c '...'` escape hatch, and each admission refusal names its one fix.
- **The unit tier is green at this head.** `go test -skip Functional ./...` passed for every package, including `verbs`, `store`, `steps`, `card` and `edge/worker`, and `verbs/core_test.go:16-96` pins the verb list, role matrix, help coverage and core refusals.

## What gets it to 10

1. **Turn `docs/SETUP.md` into the walkthrough it admits it is not.** `docs/SETUP.md:1-4` says "This is what the setup must be; layer 6 makes it exact and this page becomes the walkthrough an AI runs," and the remaining 86 lines are requirements prose with no commands. Replace sections 1-5 with a numbered transcript: `nova-fleet check`, `nova-sprint check`, the exact `nova-sprint up --as <coordinator> ...` line with the dashboard and service choices, `nova-sprint stream add`, `nova-sprint add --dry-run`, `nova-sprint start`, each with its expected first line and the one failure an AI will meet (missing Tailscale key, no commit identity, no bench cores). Done when a fresh AI with only `README.md` and `nova-sprint help` goes from zero to a running sprint twice without opening `docs/LAYER-6-RUN.md`.

2. **Expose a documented throwaway store.** `docs/LAYER-6-RUN.md:589` names `run/filestore` as a manual-test seam, but no verb, no `make` target and no SETUP section reaches it; the only documented target is the live fleet, so I could not safely try `add`, `hook`, `take`, `finish` or `read`. Add a `nova-sprint up --dev` (or `make dev-up` in SETUP) that creates a local PostgreSQL/Redis, or the file store, sets `NOVA_PG_DSN`/`NOVA_BUS_REDIS`, and prints its teardown. Done when an AI can run `stream add` -> `add --dry-run` -> `hook` -> `take` -> `finish`/`read` on that store with no production credential and `check` is green there, and the recipe runs in CI.

3. **Add a build-and-first-command block to `README.md`.** `README.md:1-24` has the banner and six promises, then line 20 says only "ask your AI to read the docs." It has no Go version, no prerequisite, no `make build`, no first command; on this bench `go` was not on `PATH` (the toolchain was at `/home/nova/sdk/go1.26.6/bin/go`). Put five lines after the banner: Go 1.26+, the nova-tools prerequisite, `make build`, `./bin/nova-sprint help`, `./bin/nova-sprint check`. Done when a new AI can go from a fresh clone to `help` without opening `docs/README.md`.

4. **Make every `help <verb>` page end with a runnable command.** `verbs/help.go:60-68` does `done("nova-sprint "+v.name+" ...")`, so `help add` ends `next: nova-sprint add ...`, `help take` ends `next: nova-sprint take ...`, and `help version` ends in a no-op loop. Add one concrete example per verb, or drop the `next:` line where nothing follows, for example `help add` -> `nova-sprint add --stream s --brief-file card.md --dry-run`. Done when `verbs/core_test.go` fails if any help page's last line ends in `...`, and `take`, `finish`, `read`, `add`, `stream add`, `show` and `next` each print a copyable command.

5. **Fix the bare `nova-sprint` / `next` cold path.** A process with no sprint credential runs `nova-sprint` and gets `NEXT this process has no sprint credential` followed by `next: run under nova-secrets exec --only ... -- nova-sprint ...` (from `verbs/result.go:48-55` and `verbs/next.go:107-130`), exit 0. That is a truncated placeholder, not a command, and it contradicts `docs/CORRECT-USE.md:29` which makes the bare command the cold AI's front door. In `unready`, detect "no store/credential yet" before the secrets text and answer `next: nova-sprint check` or `next: nova-sprint up --as <coordinator>`. Done when a fresh process with no `NOVA_*` prints a copyable `next:` command and a test in `verbs/core_test.go` pins it.

6. **Give every verb the same refusal table.** The help promise is one shape, but 15 of the 40 pages have no `refuses when` section: `queue`, `unhold`, `relink`, `replace`, `policy set`, `policy activate`, `policy show`, `policy diff`, `policy check`, `worker`, `dash`, `stop`, `start` (plus the cold `help`/`version`, which legitimately need none). `verbs/table.go:126-129` is where `show` and `queue` are defined with only one entry each. Fill in the real prerequisites and fixes for every non-cold verb, generated from the code that enforces them. 1. **At the front door, between `README.md`, `docs/SETUP.md` and `nova-sprint up`.** `README.md:20` says read the docs; `docs/SETUP.md:1-4` says it is a contract, not the walkthrough; `docs/README.md:20-23` lists Tailscale, Redis, PostgreSQL and Ansible as prerequisites and then turns into layer history. ## Tokens and time

The largest cost was reading before doing. I read `README.md` (24 lines), the first 80 lines of `docs/README.md`, `docs/SETUP.md` (90), `docs/CORRECT-USE.md` (287), `docs/CARD-CONTRACT.md` (181) and both playbooks (312 + 417), then ran `help` for all 40 verbs (327 lines of output), before I had the loop. `help playbook coordinator` alone is 731 lines because of the worker+coordinator concatenation, and the 25 verb pages that do have the `who:`/`up:`/refusal/`next:` shape repeat the same boilerplate; the other 15 omit the refusal table, so reading 25 does not let you predict the rest.

The second cost was that half the walk had to be reading rather than doing. `docs/SETUP.md` has no throwaway-store recipe, `run/filestore` is only reachable from `cmd/nova-sprint/filestore_test.go`, and the only documented target is the live fleet, so I could not exercise `add`, `hook`, `take`, `finish` or `read`; I spent time reading `docs/LAYER-6-RUN.md:589` and the filestore test to confirm there was no hidden seam. `go` was not on `PATH` (the toolchain was at `/home/nova/sdk/go1.26.6/bin`), so every build needed the export.

The third cost was cross-checking contradictions. The `...` endings on every help page, the stale DEAL sample in `docs/CORRECT-USE.md:96-97`, the ghost `edit` verb, the playbook's bare `show <id>`, the playbook's "every verb needs the credential," and the `show` usage that omits `--as` all look authoritative and do not match what the binary accepts, so each one sends an AI back to the source or the tests. Finally, `go test -count=1 -run Functional ./store` is red at this head in `TestFunctionalMigrateTwice` and `TestFunctionalMigrateRound16`, which cost time to separate from this card's own work; the unit tier (`go test -skip Functional ./...`) is green.
