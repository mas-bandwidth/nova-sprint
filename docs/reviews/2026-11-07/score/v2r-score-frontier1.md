## Score: 9/10

nova-sprint is the closest thing to a 10/10 tool for AIs I have used: every verb's `help` is a complete table (`who`, `up:`, `refuses when ... and the fix it names`, `next:`), every refusal is one line that names the command that fixes it, and the two playbooks leave nothing to memory. I was dealt this card by it, read JOB.md cold, and could act. It loses one point on the bootstrap: the first verb an AI runs that writes anything (`up`) refuses on a prerequisite (the control-seat secrets store) that no nova-sprint doc and no `help up` mention, and there is no documented throwaway-store path to learn the verbs by doing before a human is in the loop. Those two are the gap between "an AI can read and be told what to do" and "an AI can set it up and go."

## What is good

- `help <verb>` is the model to copy: `nova-sprint help take` prints usage, who, what it needs from `up`, every refusal with the command that fixes it, and the `next:` line — self-contained, no cross-reading (verbs/help.go).
- `check` is the one doctor and prints everything before failing: `CHECK RED nova-fleet check is not green ...`, `CHECK nova-tools v2.0.3 (pin v2.0.3)`, `CHECK RED this process has no sprint credential ...`, then `SPRINT REFUSED check: 3 lines are red; the first: ...`, exit 2 — all lines visible, first red's fix named (docs/CORRECT-USE.md "Built (stitch)").
- The one-rule refusal holds in practice: `up --as test` refused `SPRINT REFUSED up: control-seat secrets configuration is incomplete: set NOVA_SECRETS_STORE, NOVA_SECRETS_KEY, NOVA_SECRETS_PINS and NOVA_SECRETS_SEAT; run nova-secrets -h`, one line, exit 1.
- `next` follows CORRECT-USE's order once a credential is present: with a DSN and password in the environment it printed `NEXT nova-fleet check is not green ... next: fix what nova-fleet check names` — the fleet question first, as the docs promise.
- The card contract is enforced, not wished: CARD-CONTRACT.md "Admission" refuses a DONE-WHEN that is not one argv, a retired mechanic, or a PATHS not at base; my own card's DONE-WHEN is a `sh -c '...'` one-argv gate, so the form I was judged by is the form the tool documents.
- The playbooks are compiled into the binary: `nova-sprint help playbook worker` prints docs/PLAYBOOK-WORKER.md verbatim, so the hook a worker reads and the doc a reviewer checks cannot drift (LAYER-6-RUN.md "hook").
- `version` honestly reports an unstamped build: `nova-sprint dev`, matching Makefile's "a build with no stamp ... is 'dev' and cannot back up".

## What gets it to 10

1. Put the control-seat secrets prerequisite in the docs and in `help up`. Change docs/SETUP.md §1 ("nova-tools first") to add a first step: configure the control seat (`NOVA_SECRETS_STORE`, `NOVA_SECRETS_KEY`, `NOVA_SECRETS_PINS`, `NOVA_SECRETS_SEAT`, see `nova-secrets -h`), and add the refusal `control-seat secrets configuration is incomplete` to `help up`'s "refuses when" list (verbs/up.go). Done when: on a machine with no secrets config, `nova-sprint help up` lists that refusal and SETUP §1 names it, so the first `up` refusal is already on the page, not a surprise.

2. A throwaway-store path so a cold AI can learn by doing before the fleet exists. Add a section to docs/SETUP.md (or docs/TESTING.md) titled "try the verbs first": a `nova-sprint up --local` (or `demo`) that runs `initdb` + `redis-server` in a temp dir, makes the store at step 2, and lets the AI run `stream add ... --forge none`, `add`, `take`, `finish`, `read`, `land` and `clear` end-to-end with no Tailscale token. Done when: a cold AI, following only that section, lands a card against a local store and `clear`/`restore` round-trips, and the section states plainly that `up --local` never touches a live store.

3. Make the first-contact story match the real first output. docs/LAYER-6-RUN.md §4's transcript shows `nova-sprint` printing `NEXT the fleet is not up ...` first; the real first line on an unconfigured machine is `NEXT this process has no sprint credential`. Fix `next` to check the fleet before the store credential (so a cold AI is told "fleet not up" before being asked for a credential to a store that does not exist), or correct the transcript and CORRECT-USE "What next looks at" to show the credential line first with an explanation. Done when: `nova-sprint` on a bare machine prints, line for line, what LAYER-6 §4 promises, in the promised order.

4. A ten-line cold-start page. The shortest path to action today is SETUP + CORRECT-USE + both playbooks + CARD-CONTRACT + LAYER-6, about 1,300 lines. Add docs/START.md (and a verb for it — `start` is already the tick verb, so e.g. `help walkthrough`): the literal commands from zero to first landed card, each line annotated with the doc it expands. Done when: an AI that reads only START.md and follows `next` reaches `stream add` with no dead-end, and every command in START.md is held to an existing verb by the help-index test (LAYER-6 §10).

5. Mark which verbs stop for a human. `up` pauses for a Tailscale token (step 1) and service keys (step 6), and `stream add --forge github` needs `gh` write access; a cold AI starts `up` expecting to finish it unattended. Add to `help`'s index and `help up` a "stops for the human:" line per verb (or a `[needs human]` tag). Done when: `help` tells an AI, before it runs, that `up` will stop at steps 1 and 6 for a human paste, so it schedules the human and works `next`/`check` in the meantime instead of blocking.

## Where I would be lost cold

1. The first `up`: `SPRINT REFUSED up: control-seat secrets configuration is incomplete: set NOVA_SECRETS_STORE, ...`. This prerequisite is in neither SETUP.md nor `help up`; I had to leave the nova-sprint docs and read `nova-secrets -h`. That is a second tool's configuration appearing as a surprise in the middle of the bootstrap.
2. After SETUP.md, trying to actually do anything: `up` needs a human's Tailscale token paste, and `take` refused `nova-bus who failed ... missing NOVA_BUS_REDIS` (exit 2) because there is no bus. There is no documented throwaway store, so between "read the docs" and "the human pastes the token" an AI can only re-read and run `check`/`next`. The one functional test I could run (`TestFunctionalEndToEnd`) failed on its own fake `gh` shim (`gh repo view ... is not faked`), so it gave me no store to try either.
3. The bare `nova-sprint` first line, `NEXT this process has no sprint credential`, asks for a credential to a store that does not exist yet, before the tool says the fleet is down. A cold AI would chase nova-secrets setup for a database it cannot yet reach.

## Tokens and time

What cost me the most was the bootstrap dead-end. I could not exercise a single state-changing verb against a store, because `up` is gated on a human's Tailscale token and the control-seat secrets config, so I inferred most behavior from ~1,300 lines of docs (SETUP, CORRECT-USE, both playbooks, CARD-CONTRACT, LAYER-6) plus `help <verb>` for about twenty verbs. The playbooks, excellent as they are, run ~300 and ~417 lines and must be read before acting; the `help` index is dense enough that I had to run `help <verb>` one at a time to map the surface. The documentation is the product and it is long: the cost was to understand, not to do.
