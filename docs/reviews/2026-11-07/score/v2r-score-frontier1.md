## Score: 9/10

nova-sprint is the best AI-facing tool I have walked this year: every verb prints a self-contained table (`who`, `up:`, `refuses when ... and the fix it names`, `next:`), every refusal is one line that names the command that fixes it, and the playbooks are compiled into the binary so the hook a worker reads and the doc a reviewer checks cannot drift. I was dealt this card by it, read the brief cold, and could act with no human. It is not a 10 for one concrete reason: an AI with no memory cannot "set it up and go." The first verb that writes anything (`up`) refuses on a prerequisite — the control-seat secrets store (`NOVA_SECRETS_STORE`, `NOVA_SECRETS_KEY`, `NOVA_SECRETS_PINS`, `NOVA_SECRETS_SEAT`) — that no nova-sprint doc and no `help up` mention, and there is no documented throwaway-store path to learn the verbs by doing before a human pastes the Tailscale token. Everything after the fleet exists is a 10; the bootstrap is not, and the SETUP.md dogfood gate says that bootstrap is the whole point.

## What is good

- `help <verb>` is the model to copy: `nova-sprint help take` prints usage, `who: worker or coordinator`, `up: the store up makes at step 2 ... without it: nova-sprint up`, a `refuses when (and the fix it names)` list, and `next: nova-sprint take ...` — self-contained, no cross-reading (verbs/help.go). I mapped the whole surface from these tables alone.
- `check` is one doctor and prints everything before failing: on a bare machine it printed `CHECK RED nova-fleet check is not green ...`, `CHECK nova-tools v2.0.3 (pin v2.0.3)`, `CHECK RED this process has no sprint credential ...`, `CHECK RED nova-bus who failed ...`, then `SPRINT REFUSED check: 3 lines are red; the first: ...` — every red line visible, each naming its fix (docs/CORRECT-USE.md "Built (stitch)").
- The one-rule refusal holds in practice: `up --as frontier1` refused with exactly one line, `SPRINT REFUSED up: control-seat secrets configuration is incomplete: set NOVA_SECRETS_STORE, NOVA_SECRETS_KEY, NOVA_SECRETS_PINS and NOVA_SECRETS_SEAT; run nova-secrets -h`, exit 1.
- The card contract is enforced, not wished: docs/CARD-CONTRACT.md "Admission" refuses a DONE-WHEN that is not one argv and names retired mechanics (`WHO:`, `LOCK:`, `JOB.md`, `ssh to <host>`); my own card's DONE-WHEN is a `sh -c '...'` one-argv gate, so the form I am judged by is the form the tool documents (`edge.ParseGate`).
- The playbooks are compiled into the binary: `nova-sprint help playbook worker` prints docs/PLAYBOOK-WORKER.md verbatim (313 lines), so what a worker's hook prints cannot drift from what a reviewer checks (docs/LAYER-6-RUN.md "hook").
- `version` is honest about an unstamped build: `nova-sprint dev`, matching the Makefile's "a build with no stamp is 'dev'".

## What gets it to 10

1. Put the control-seat secrets prerequisite in the docs and in `help up`. Change docs/SETUP.md §1 ("nova-tools first") to add a first step — configure the control seat (`NOVA_SECRETS_STORE`, `NOVA_SECRETS_KEY`, `NOVA_SECRETS_PINS`, `NOVA_SECRETS_SEAT`, see `nova-secrets -h`) — and add the refusal `control-seat secrets configuration is incomplete` to `help up`'s "refuses when" list (verbs/up.go). Done when: on a machine with no secrets config, `nova-sprint help up` lists that refusal and SETUP §1 names it, so the first `up` refusal is already on the page instead of a surprise that sends the AI to a second tool's help.

2. A throwaway-store path so a cold AI can learn by doing before the fleet exists. Add a section to docs/SETUP.md (or docs/TESTING.md) titled "try the verbs first": a `nova-sprint up --local` (or `demo`) that runs `initdb` + `redis-server` in a temp dir, builds the store at step 2, and lets the AI run `stream add ... --forge none`, `add`, `take`, `finish`, `read`, `land` and `clear` end-to-end with no Tailscale token. Done when: a cold AI, following only that section, lands a card against a local store and `clear`/`restore` round-trips, and the section states plainly that `up --local` never touches a live store.

3. Make the first-contact story match the real first output. docs/LAYER-6-RUN.md §4's transcript shows a bare `nova-sprint` printing a greeting ("nova-sprint deals cards to AIs ...") and `NEXT the fleet is not up ...`; the real first line on an unconfigured machine is `NEXT this process has no sprint credential` (there is no greeting string in cmd/nova-sprint/main.go, and verbs/next.go's `look` reads the store before it calls the fleet doctor). Fix `next` to check the fleet before the store credential, or correct the transcript and CORRECT-USE "What next looks at, in order" to show the credential line first with an explanation. Done when: `nova-sprint` on a bare machine prints, line for line and in the promised order, what LAYER-6 §4 shows.

4. A ten-line cold-start page. The shortest path to action today is SETUP + CORRECT-USE + both playbooks + CARD-CONTRACT + LAYER-6, roughly 1,300 lines. Add docs/START.md: the literal commands from zero to the first landed card, each line annotated with the doc it expands. Done when: an AI that reads only START.md and follows `next` reaches `stream add` with no dead-end, and every command in START.md is held to an existing verb by the help-index test (docs/LAYER-6-RUN.md §10).

5. Mark which verbs stop for a human. `up` pauses for a Tailscale token (step 1) and service keys (step 6), and `stream add --forge github` needs `gh` write access; a cold AI starts `up` expecting to finish it unattended. Add a "stops for the human:" line per verb to `help`'s index and `help up` (or a `[needs human]` tag). Done when: `help` tells an AI, before it runs, that `up` will stop at steps 1 and 6 for a human paste, so it schedules the human instead of blocking.

## Where I would be lost cold

1. The first `up`: `SPRINT REFUSED up: control-seat secrets configuration is incomplete: set NOVA_SECRETS_STORE, ...`. This prerequisite is in neither SETUP.md nor `help up`; I had to leave the nova-sprint docs and read `nova-secrets -h`. A second tool's configuration surfaces as a surprise in the middle of the bootstrap.
2. After SETUP.md, trying to actually do anything: `up` needs a human's Tailscale-token paste, and there is no documented throwaway store, so between "read the docs" and "the human pastes the token" an AI can only re-read and run `check`/`next`. The functional test that would have given me a store (`TestFunctionalEndToEnd`) fails on its own fake `gh` shim, so it was no store to try either.
3. The bare `nova-sprint` first line, `NEXT this process has no sprint credential`, asks for a credential to a store that does not exist yet, before the tool says the fleet is down. A cold AI chases nova-secrets setup for a database it cannot yet reach, and the docs' own transcript promises a different first line than the binary prints.

## Tokens and time

What cost me the most was the bootstrap dead-end: I could not exercise a single state-changing verb against a store, because `up` is gated on a human's Tailscale token and the control-seat secrets config, so I inferred most behavior from the ~1,300 lines of docs plus `help <verb>` for the surface. The playbooks are excellent but long (~312 and ~400 lines) and must be read before acting; the `help` index is dense enough that I had to run `help <verb>` one at a time to map the verbs. The documentation is the product and it is long — the cost was to understand, not to do — and the largest single waste is that no page tells a cold AI the three things that come first, in order.
