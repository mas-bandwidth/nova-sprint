## Score: 7/10

Walked for real, not from the docs: this build (dev+a4cfdc6f88ce) against a throwaway PostgreSQL 18 and Redis I started and removed myself (never the live store), with three names on a throwaway bus, a local bare origin, and `run` serving on 127.0.0.1. From the moment the store existed, the tool is as good as any I have used: every refusal I provoked (`take` at a wrong gen, `finish` with a short sha, `finish` with a commit by the wrong author, `read fix` with no finding, `read` by a non-holder, `judge` of an expired judgement) was one line naming its exact fix, the DEAL message carried everything a child needs, and one card went add -> deal -> take -> finish -> read -> hand landing in eight minutes of typing. It is not a 10 because the first half hour is not usable cold: `up` cannot run at all without a nova-secrets control seat and a human's Tailscale token, there is no documented way to get a store to learn on, and once a store exists by other means the tool itself strands an AI three times (no policy and no verb that prints the built-in one; a `roster` judgement on the coordinator that reopens every tick after the only answer it offers; `next` sending the coordinator to `start` while `check` is red on identity, policy and run). Add the defects I hit on the way (`backup` fails on a long TMPDIR; the end-to-end functional test is red at this head; the coordinator playbook names an `edit` verb that does not exist; `up` refuses under the playbook's own "run every verb under nova-secrets exec" rule), and 7 is the honest number: the engine and the verbs are 9 to 10, the road to them is 4.

## What is good

- The refusals are exact and copy-pasteable. `finish lab1.w1@0 --head <wrong-author sha>` printed `1 of the 1 commits on sprint/s/lab1 since the base are not made as lab-bot <...>: 7039f2253f54 (author kim@sprint.test, committer kim@sprint.test): in the clone run git config user.name "lab-bot" and git config user.email "...", then rewrite those commits as it (git rebase 238fbaa9... --exec 'git commit --amend --no-edit --reset-author'), git push --force-with-lease origin sprint/s/lab1, and finish with the new head` (verbs/head.go). I did exactly that and the next `finish` printed `FINISHED lab1.w1 head=d1b0ba19... applied at seq 18`. `finish --head abc123` said `pass the 40-hex sha git ls-remote origin sprint/s/lab1 prints`; `read ... fix` with no finding said `add --finding "<path>:<line>: <the defect and the repair>"`.
- The DEAL push is the whole job. kim's inbox got one line: `DEAL card=lab1.w1 attempt=1 kind=work stream=s tier=pro model=m-kim epoch=1 repo=<path> base=238fbaa9... branch=sprint/s/lab1 brief=<clipped>; in your hand now: run nova-sprint take lab1.w1@0 --epoch 1 --as kim (...), then do it and run: nova-sprint finish lab1.w1@0 --head <sha> --as kim --epoch 1`, and the read deal the same with `head=`. A child can be started from that line alone (docs/PLAYBOOK-WORKER.md "What arrives on the bus", item 1, matches the real text).
- `take` prints the commit identity and the two `git config` lines before the brief, and `--json` gives the same as a record (`base_sha`, `branch`, `paths`, `done_when`, `deadline`): a harness can parse it, a model can read it.
- `add --dry-run` catches the brief before anything exists. My bad gate `DONE-WHEN: test -f lab.txt && grep done lab.txt` was refused with `line 4 ... is not one command: && is shell syntax (nothing runs a shell): ... wrap it: sh -c '...'` (verbs/brief_lint.go, edge.ParseGate); the good one printed `ADD lab1 ... CHAIN stream s: its longest NEEDS chain is 1 cards` and `(dry run)`.
- `help <verb>` is one self-contained table (`who:`, `up:`, `refuses when (and the fix it names)`, `next:`), 41 of them, and the index groups them start/work/coordinate/operate with `[cold (no hook needed)]` on the ones that run before a hook (verbs/help.go). I mapped the surface from the index and ten tables.
- `check` after the store exists is the doctor it claims to be: it named, each with its fix, the missing identity, the missing policy, the free chooser lock, then later each open judgement by id with its choices and `landing s: 1 merging (lab1) waits for ...` (verbs/check*.go).
- The landing by hand is honest and complete: with `forge=none` the tick opened `land.lab1.1` with the base, branch, head and the three choices; `judge land.lab1.1 land --reason ...` printed `LANDED lab1 head=... merge=... by hand`, origin's `main` moved to the head, and carol was pushed `STREAM LANDED s 1 landed; run: nova-sprint show s --stitch`.
- `stop` works at once and `next` for a worker says why nothing comes (`the sprint is stopped (lab done)`); `unhook` names the hook that puts you back.

## Where I would be lost cold

1. **At `nova-sprint up --as <me>`, before anything exists.** `SPRINT REFUSED up: control-seat secrets configuration is incomplete: set NOVA_SECRETS_STORE, NOVA_SECRETS_KEY, NOVA_SECRETS_PINS and NOVA_SECRETS_SEAT; run nova-secrets -h` (cmd/nova-sprint/up_wrapper.go). None of docs/SETUP.md, docs/README.md or `help up` says this comes first; `nova-secrets -h` is four commands and an age key before I am back in nova-sprint; and behind it is a human's Tailscale token (`nova-fleet check`). With no `--local`, a cold AI's first hour is reading, not doing.

2. **On a store `up` did not make, at `check`'s `no policy is active`.** The fix line offers `nova-sprint up` (refused, above) or `policy activate <version>` (there is none); `policy set <file>` wants a Starlark file; `policy show default` refuses (`a version is 7 or v7`); `policy check default` says `0 answer(s) change ... next: nova-sprint policy set <file>` with no file. I got the default from the repository (policy/default.star). An AI with the binary and not the source cannot.

3. **As the coordinator, at the first `next` after `hook`.** `next --as carol` said `stream add`, then `add`, then `start`, and never mentioned the identity, the policy or the run that `check` was red on; after `start` every `next` named `judgement roster.carol.1 needs you` with the single choice `retry`, which reopened it as `roster.carol.2`. An AI that trusts `next` (as CORRECT-USE tells it to) starts a sprint that deals nothing and then answers the same judgement forever.
