## Verdict

Layer 5's Starlark embedding, closed question set, per-answer domain validators (`policy/validate.go`), joint dealability check (`policy/answer.go:168-189`), and `tla/Policy.tla` fallback structure are cleanly separated from store mutations, **but Layer 5 is not ready to clear without fixing three serious defects in deadline enforcement and child-evaluator fault recovery**:

1. `Engine.deadline` (`policy/clock.go:29-39`) spawns an asynchronous timer goroutine without checking whether `e.budget - e.clock.Now().Sub(start) <= 0`, and `run.await` (`policy/tick.go:101-118`) races `<-r.ready` against `<-r.ctx.Done()` without checking `r.ctx.Err()`. When a tick starts with an already-expired deadline (as in `TestDeadlineOnTheClock`, `policy/round5_test.go:19-33`), `AnswerContext` can miss the expired deadline and return `Answers{Version: 0}` with 2 failures instead of `Answers{Version: -1}` with 3 failures.
2. `evaluator.send` (`policy/evaluator.go:173-189`) and `Engine.remote` (`policy/evaluator.go:114-116`) fail to call `ev.stop()` when `ev.enc.Encode(req)` returns an error (such as `EPIPE` after the child evaluator exits between ticks), leaving the dead `ev.cmd` installed so every subsequent tick or `check` on that `Engine` fails permanently.
3. The out-of-process evaluator path (`policy/answer.go:61-63`, `policy/evaluator.go:102-134, 282-284, 300`) bypasses `e.deadline(ctx, start)` in the parent, sends requests to the child even when `req.Budget <= 0`, and hardcodes `RealClock{}` and constant `fallbackAfter = TickTime / 2` (`policy/tick.go:81`) inside the child regardless of the parent's `Clock` or remaining `req.Budget`.

## Defects

Ranked most severe first (`blocker`, `serious`, `minor`, `nit`), with `file:line`, mechanism, impact, and concrete repair.

1. **[blocker] `policy/clock.go:29-39` and `policy/tick.go:81-118` (`Engine.deadline`, `Engine.race`, `run.await`) — asynchronous deadline cancellation races with fast in-process evaluation and causes `TestDeadlineOnTheClock` (`policy/round5_test.go:26-27`) to fail under load.**
   - **What breaks:** In `policy/clock.go:29-39`, `deadline` computes `fire := e.clock.After(e.budget - e.clock.Now().Sub(start))` and spawns a goroutine `go func() { select { case <-fire: cancel() ... } }()`, returning `ctx` immediately. When the budget is already exhausted (`e.budget - e.clock.Now().Sub(start) <= 0` or `c.expire()` in `policy/round5_test.go:23`), `ctx` is still uncancelled until the spawned goroutine is scheduled. `AnswerContext` (`policy/answer.go:64-74`) checks `if ctx.Err() != nil` at line 67, sees `nil`, and enters `e.race` (`policy/tick.go:74-97`). Worse, in `run.await` (`policy/tick.go:101-118`), `select` chooses nondeterministically between `case o := <-r.ready:` (`policy/tick.go:104`) and `case <-r.ctx.Done():` (`policy/tick.go:110`), and even inside `case <-r.ctx.Done():` lines `111-113` prefer `case o := <-r.ready: return o` if `r.exec()` finished before `r.ctx` was cancelled. Under CPU contention (`GOMAXPROCS=4`), `v3` and `v2` fail on the deadline, `early()` launches `default`, and `default` completes from compiled state or before `cancel()` is observed, returning `a.Version == 0` and `len(fs) == 2` instead of `-1` and `3`.
   - **Repair:** In `policy/clock.go:29-39`, if `rem := e.budget - e.clock.Now().Sub(start); rem <= 0` (or `select { case <-fire: cancel(); return ctx, cancel; default: }`), call `cancel()` synchronously before returning `ctx`. In `policy/tick.go:101-118` (`run.await`) and `policy/tick.go:90` (`Engine.race`), check `r.ctx.Err() != nil` before accepting a clean `o` (`len(o.fs) == 0`), converting any post-deadline completion into `outcome{fs: []Failure{r.late()}}`.

2. **[serious] `policy/evaluator.go:114-116, 173-189` (`Engine.remote`, `evaluator.send`) — an encode error on `ev.enc.Encode(req)` neither calls `ev.stop()` nor stops the spawned `dec.Decode` goroutine, wedging the `Engine` across all future ticks.**
   - **What breaks:** In `policy/evaluator.go:173-189`, `ev.send` starts a reader goroutine (`go func() { dec.Decode(&rep) ... }()`, lines `180-187`) before calling `return ev.enc.Encode(req)` (line `188`). In `policy/evaluator.go:114-116`, if `ev.send` returns a non-nil error (for example, `EPIPE` when the child `policy-eval` process died or was OOM-killed between ticks, or a gob encoding error on a large request), `remote` returns `killed(failing, err.Error())` without calling `ev.stop()`. Because `ev.cmd` is only cleared in `ev.stop()` (`policy/evaluator.go:216-224`), `ev.cmd` remains non-nil and every subsequent call to `AnswerContext`, `Check`, or `ReadCatalog` on that `Engine` reuses the broken pipe and fails permanently instead of spawning a new child on the next request (`docs/LAYER-5-POLICY.md:951-953`, `policy/evaluator.go:31`).
   - **Repair:** Call `ev.stop()` inside `if err := ev.send(req, got, errc); err != nil` at `policy/evaluator.go:114-116` (or inside `ev.send` when `ev.enc.Encode(req)` fails), and start the `dec.Decode` goroutine only after `ev.enc.Encode(req)` succeeds (or ensure `ev.stop()` closes the stdout pipe so the reader goroutine exits immediately).

3. **[serious] `policy/answer.go:56-64`, `policy/catalog.go:59-64`, `policy/show.go:88-93`, and `policy/evaluator.go:102-134, 282-284, 300` — out-of-process `Engine` bypasses parent `Clock` budget check before IPC and runs child `ServeEval` on `RealClock{}` with unscaled `fallbackAfter`.**
   - **What breaks:** When `e.proc != nil` (`NewEngine`), `AnswerContext` (`policy/answer.go:61-62`), `catalog` (`policy/catalog.go:60-61`), and `checkRun` (`policy/show.go:89-90`) return `e.remote(...)` before calling `e.deadline(ctx, start)`. In `e.remote` (`policy/evaluator.go:105-108`), `req.Budget` is set to `e.budget - e.clock.Now().Sub(start)`, but line `106` only checks `if ctx.Err() != nil` (the caller's context, not `req.Budget <= 0`). Even when `req.Budget <= 0` on `e.clock`, `remote` still clones and gob-encodes the snapshot to the child and waits on `e.clock.After(req.Budget + evalGrace)` (`policy/evaluator.go:129`). Inside the child, `ServeEval` (`policy/evaluator.go:283`) hardcodes `newLocal(RealClock{})` and `serve` (`policy/evaluator.go:300`) sets `e.budget = req.Budget`, while `Engine.race` (`policy/tick.go:81`) schedules speculative fallback at `fallbackAfter = TickTime / 2` (`policy/engine.go:45`) rather than `e.budget / 2`.
   - **Repair:** In `policy/evaluator.go:105-108`, refuse immediately with `killed(failing, overTime()+" building the tick's inputs")` when `req.Budget <= 0 || ctx.Err() != nil`. In `policy/tick.go:81`, compute speculative fallback relative to `e.budget / 2` instead of the package constant `fallbackAfter`.

4. **[minor] `policy/verbs.go:326-328` (`LoadVersions`) — error from `st.Policy(ctx, prev)` still assigns non-nil `vs.Prev` pointing to a zero `store.PolicyVersion`.**
   - **What breaks:** At `policy/verbs.go:326-328`, `LoadVersions` runs `p, err := st.Policy(ctx, prev); vs.Prev = &p; return vs, err`. Whenever `st.Policy(ctx, prev)` returns a non-nil error, `vs.Prev` is populated with `&store.PolicyVersion{Version: 0, Body: ""}` rather than remaining `nil`. A caller that inspects `vs` alongside or after logging the error sees a bogus `Prev` with `Version: 0`.
   - **Repair:** Check `if err != nil { return vs, err }` before assigning `vs.Prev = &p` at `policy/verbs.go:326-328`.

5. **[minor] `policy/trace.go:62, 82-92, 96-101` (`TraceState`) and `policy/show.go:141` / `policy/diff.go:37` (`Show`, `Diff`) — `Kind == "data"` policy rows are not filtered out by `TraceState`, `Show`, or `Diff`.**
   - **What breaks:** `tla/Policy.tla:16-17` states that "the model holds no data rows, which the code counts but never runs." While `Activate` (`policy/verbs.go:188`), `Check` (`policy/show.go:53`), `ReadCatalog` (`policy/catalog.go:46`), and `sameBody` (`policy/verbs.go:146`) filter or refuse `Kind != "script"` via `script()` (`policy/verbs.go:279-285`), `TraceState` (`policy/trace.go:62, 82-92`) loads all rows from `versions(ctx, st)` without checking `pv.Kind == "script"`, compiling any `data` row as Starlark in `runs.checkRun` (`policy/trace.go:83`) and recording it in `m.Breaks` and `m.Stored`. Likewise, `Show` (`policy/show.go:141`) and `Diff` (`policy/diff.go:37`) call `version()` (`policy/verbs.go:269-275`) instead of `script()`, allowing `policy diff` to diff Starlark policies against `data` blobs.
   - **Repair:** Filter `pv.Kind == "script"` in `sources` / `TraceState` (`policy/trace.go:82-92, 96-101`) and use `script()` in `Diff` (`policy/diff.go:37`).

6. **[minor] `policy/verbs.go:289-301, 318-322, 348-362` (`versions`, `LoadVersions`, `walk`) and `policy/show.go:145-161, 178-190` (`Show`, `List`, `reasons`) — unbounded O(events) log walks and O(versions) sequential store queries on cold start and CLI reads.**
   - **What breaks:** `walk` (`policy/verbs.go:348-362`) reads every event from sequence `0` up to `to` (or the entire log when `to == 0` in `reasons`, `policy/show.go:180`), and is called on every `LoadVersions` (`policy/verbs.go:318`), `Show` (`policy/show.go:145`), `List` (`policy/show.go:158`), and `TraceState` (`policy/trace.go:67`). Similarly, `versions` (`policy/verbs.go:289-301`) issues sequential `st.Policy(ctx, v)` round-trips for `v = 1, 2, ...` until `store.ErrNotFound` on every `Up` (`policy/verbs.go:58`), `Set` (`policy/verbs.go:126, 142`), `List` (`policy/show.go:154`), and `TraceState` (`policy/trace.go:62`).
   - **Repair:** Expose a bulk policy list and stored creation reason (or previous-active version) from Layer 1 `store`, or scan backwards from `snap.Seq` when only the most recent activation (`LoadVersions`) is needed.

7. **[nit] `policy/functional_test.go:23, 55`, `policy/round5_test.go:73`, and `policy/verbs_test.go:219` — functional and load tests run in plain `go test ./policy/...` without opt-in guards.**
   - **What breaks:** `docs/LAYER-5-POLICY.md:27, 330` promises that the unit test tier for `policy` runs with "no time, no sockets, no store" and no child processes. However, `TestFunctionalLoad` (`policy/functional_test.go:23`, which asserts a `500ms` wall-clock budget at line `49`), `TestFunctionalEvaluatorMemoryCap` (`policy/functional_test.go:55`), `TestFunctionalEvaluator` (`policy/round5_test.go:73`), and `TestFunctionalVerbsPG` (`policy/verbs_test.go:219`) have no `NOVA_FUNCTIONAL` / `NOVA_LOAD` skip guard and execute during an unfiltered `go test ./policy/...`.
   - **Repair:** Gate `TestFunctional*` in `policy/` behind `NOVA_FUNCTIONAL` (and `TestFunctionalLoad` behind `NOVA_LOAD`, matching `policy/coldread2_test.go:195`), or document `-skip Functional` as the required unit-test invocation.

## Model vs code

- **`Set(v)` on an uninitialized store (`tla/Policy.tla:61-67, 74-82` vs `policy/verbs.go:107-109, 121-136`):** `tla/Policy.tla` starts at `Init` (`tla/Policy.tla:61-67`, after `up`, where `stored = {1}` and `active = 1`) and models `Set(v)` (`tla/Policy.tla:74-82`) with `UNCHANGED <<active, everActive, judgements>>`. In `policy/verbs.go:107-109, 121-136`, `Set` called before `Up` (`snap.Policy == 0`) both stores `v`, activates `v`, and answers `OpenJudgements(snap, 0)`. This pre-`up` transition is outside `Policy.tla`'s `Init`.
- **`WaitKeepsItsBound` (`tla/Policy.tla:134-136, 168` vs `policy/trace.go:35-38`):** `tla/Policy.tla:168` checks `WaitKeepsItsBound == card = "working" => waitBound = startBound`, but as `policy/trace.go:35-38` notes, `waitBound` and `startBound` are not projected from Go state in `TraceState` (`policy/trace.go:45-48`) because Layer 5 holds no card wait state (Layer 3 owns wait deadlines). Thus `PolicyTrace.tla` computes `waitBound` and `startBound` purely inside the TLA+ action (`tla/PolicyTrace.tla:14-16`), so trace validation does not verify `WaitKeepsItsBound` against Go code.
- **Data policy versions (`tla/Policy.tla:16-17` vs `policy/trace.go:82-92`):** `tla/Policy.tla:16-17` assumes `stored` contains only runnable policy versions (`1..MaxVersion`), whereas `TraceState` (`policy/trace.go:62, 82-92`) includes `Kind == "data"` rows in `m.Stored` and `m.Breaks` (Defect 5).
- **Pre-expired tick deadline (`tla/Policy.tla:119-123, 127-140` vs `policy/clock.go:29-39`, `policy/tick.go:81-118`):** In `tla/Policy.tla:120-123`, when `Tried \subseteq breaks`, `Tick` deterministically produces `answeredBy' = NoAnswer` and `Failing = Tried`. In the Go implementation, the timer goroutine race in `Engine.deadline` and `run.await` (Defect 1) allows `default` to answer even when the clock expired before the tick began.

## Simplifications

- **Cancel already-expired budgets synchronously in `Engine.deadline` (`policy/clock.go:29-39`):** Computing `rem := e.budget - e.clock.Now().Sub(start)` once, immediately cancelling `ctx` without spawning a goroutine when `rem <= 0`, and scaling `spec` in `Engine.race` (`policy/tick.go:81`) by `e.budget / 2` eliminates the goroutine scheduling race (Defect 1) and unifies parent and child budget handling (Defect 3).
- **Single cleanup path in `Engine.remote` (`policy/evaluator.go:114-134`):** Calling `ev.stop()` on every error branch of `remote` (including `ev.send` failure at line `114`) and starting the gob decode goroutine only after `ev.enc.Encode(req)` succeeds removes the wedged-evaluator state (Defect 2) in three lines.
- **Unify `script` vs `version` lookups (`policy/verbs.go:269-285`):** Using `script()` in `Diff` (`policy/diff.go:37`) and filtering `pv.Kind == "script"` in `versions()` (or a dedicated `scriptVersions()` helper) avoids repeating kind checks across `Set`, `Activate`, `Check`, `ReadCatalog`, and `TraceState`.

## Missing tests

- **Deterministic pre-expired deadline test under parallel load (`policy/round5_test.go:19-33`, `policy/clock.go:29-39`):** Run `TestDeadlineOnTheClock` with `-count=100 -cpu=4` and add a counterpart on `NewEngine(c)` (where `c` is an expired `fakeClock`) verifying that both in-process and child-evaluator engines deterministically return `Answers{Version: -1}` and 3 `Failure`s without racing the scheduler.
- **Child evaluator crash/kill between ticks (`policy/evaluator.go:114-116, 173-189`):** Start a `NewEngine`, run one tick to spawn the `policy-eval` child, kill `e.proc.cmd.Process` outside `remote` so the next `ev.enc.Encode(req)` hits `EPIPE`, and verify that the subsequent tick restarts the child and succeeds rather than failing every future tick with `broken pipe`.
- **`LoadVersions` error on `st.Policy(ctx, prev)` (`policy/verbs.go:326-328`):** Inject a store fault on the second `st.Policy` call in `LoadVersions` and assert that `vs.Prev == nil` when `err != nil`.
- **`TraceState` and `Diff` with a `Kind == "data"` policy row (`policy/trace.go:82-92`, `policy/diff.go:37`):** Store a `Kind: "data"` policy row alongside active script versions and verify `TraceState` does not include the data row in `Breaks` and `Diff` refuses `Kind == "data"` with a `*Refusal`.
