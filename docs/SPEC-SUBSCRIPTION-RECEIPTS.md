# Paired subscription receipts (v1.2.19)

`subscription` is an explicit route/provider billing declaration. Its marginal per-card USD is zero without token-price arithmetic, even when tokens are absent or a legacy sheet is present. `plan` retains metered-value prediction; metered pricing remains unchanged. An explicit route declaration wins; only an absent route declaration inherits a subscription provider declaration. Names, harnesses, zero prices and token sums never choose billing.

Each launch receives its effective declaration in Packet.billing and stores it on the consumer card. Replay and repricing preserve that launch/receipt provenance if current configuration changes or disappears. A raw harness dollar field, including reported zero, remains Actual with its original ActualBy; it is evidence from the harness, never a provider invoice or the subscription's marginal charge. MarginalUSD is the projection used by charged totals, spend/reconciliation, route/read statistics and logs. Monthly subscription fees remain outside per-card accounting. The older read `billing=subscription` marker remains readable and now retains reported raw dollars while its marginal charge is zero.

The native common token projection remains unchanged. Receipt contract 2 adds `receipt_version=2`, `billing=<declared>` and optional `raw_usage=<base64url JSON>`. A Muse contract-2 receipt requires the raw record. The JSON envelope is `{version:1,records:[...]}`; each record names harness `muse`, execution `fleet`, source schema `muse-jsonl-v1`, producer version, declared billing and a tokens map using the original names: input_tokens, output_tokens, cached_tokens, cache_write_tokens, cache_read_tokens and reasoning_tokens. Counters absent from the source remain absent; reported zero remains zero. Original cache/input overlap and output/reasoning overlap remain evidence. Raw records concatenate in launch order across native attempts and durable receipt replay; their counters are never added to common token totals or multiplied by prices.

Checked spend/usage decoders refuse unsupported versions, malformed envelopes and negative/overflow counters before a consumer is written. Legacy common spend strings remain accepted on legacy compatible routes. Contract 2 requires `--receipt-contract 2` on finish/read. The old local parser and old forwarded-server parser reject the unknown flag before accessing the store. The new parser rejects contract 2 without its complete typed receipt, or typed receipt without its flag. The planner independently refuses malformed receipts, missing contract 2 on a typed subscription route, billing inconsistent with the original launch, and a Muse contract-2 receipt missing raw provenance.

Supported adoption is a staged installation followed by atomic activation: first install the compatible new sprint server/receiver and all fleet member/native binaries while retaining the existing Muse plan-plus-zero-price bridge. Old packets without Billing remain explicitly legacy and make no raw/version-2 claim. New members pass billing explicitly to new native; an old native rejects the new billing flag. Activate typed subscription only after the paired binaries and migration are accepted. An old member's flattened legacy receipt on a newly typed subscription route is refused before durable write, never reconstructed into invented raw evidence. Do not roll an old schema/reader back onto a contract-2 activated store; retain the compatible receiver for restore/replay. All adoption tests use fake stores/serializers, with no live route, schema, keys, provider request or install.

The repositories own independent copies of pkg/cardcost. The producer owns the new raw.go codec, mirrored byte for byte with its exact SHA-256 in the paired evidence. Existing decimal/predict/usage changes are scoped and mirrored, rather than importing unrelated producer commits. The deliberate legacy divergence is preserved: sprint drops legacy nonsubscription harness zero on an unpriced token run; tools retains it. Contract-2/subscription receipts preserve reported zero in both. Exact paired source SHAs and codec digest belong to the final evidence manifest and companion PR pins; no self-referential commit hash is embedded in source.
