# s5. Reads (rationale)

The reads were dealt one at a time more than once, and each time the owner restated the
requirement. The owner, 2026-10-06: "I don't want any serial reads again. That was silly."; "send
out multiple consumer cards in ||"; "Just remove the complexity. just deal it."; 2026-10-11:
"Multiple reads now go out in ||"; "reads should keep going, every second, even if there is no
capacity. It repeats over and over until there is"; 2026-10-18: "if we have serial reads again,
I'm going to be really sad" and "the parallel reads is a design requirement." R-READS-PARALLEL is
hard row H1.

The code is `internal/sprint/read_cards.go`: `readCardsWanted` is the reads an attempt wants now
(R-READS-WANTED), `readCardsAsk` deals every primary's wanted reads in one step, each to a
different unit (R-READS-PARALLEL, R-READ-CHEAPEST), `mayReadCard` and `readRefusal` say who may
read (R-READER-NEVER-WORKER, R-READER-DISTINCT, R-READ-TIER), and `readTierDistance` orders them
by tier. The model is `tla/ReadCards.tla` (OneOpenPerReader, AtMostNeedStanding, NeverTheWorker,
NeverTwiceAfterSpent, MergingOnlyOnOks, OkReadsAccept, CompleteView, NeverWedged). The
description is docs/SPEC-SPRINT.md section 6, "A read is a consumer card", and section 1, the
read-card deal.

- R-READ-COUNT: the owner, 2026-10-02, cost rule 4: "Reads: one cold read per flash card on a
  flash route; two per pro card"; 2026-10-06: "I'd like to waive the second read for the moment"
  (`set --reads`).
- R-READ-TIER: the owner, 2026-10-16: "It is completely undefined that a card should run at the
  wrong tier."
- R-READ-CHEAPEST: the owner, 2026-10-11: "Deal logic should be using ((index++) % n) to roll
  around, not hitting the same fleet machine or friend each deal"; "cards only may accrue
  per-fleet or friend, if there are not other machines/friends ready to do that work right now!"
- R-READ-TAKEBACK: on 2026-10-15 forty review cards had no reads dealt: every fleet reader's reads
  had been taken back off a resting route five times and then refused for good as past the load
  window; the read top (`PropReadGenTop`, v1.4.4) ended it (`tla/ReadCards.tla` NeverWedged).
- R-READ-BRANCH-MISSING: on 2026-10-06 about half of one reader's 54 broken verdicts said the
  branch the read named was not on origin, and each sent its card to rework
  (`internal/sprint/read_missing.go`, `tla/ReadBranchMissing.tla`).
- R-READ-DEADLINE: `ReadCardDeadline`, one hour from the take; a read never taken is taken back at
  the deal bound and spends no one.

R-READS-PARALLEL's Go pins assert the all-at-once deal, but the existing ReadCards model
has no gated property for that obligation. Its Deal action permits any nonempty subset of
eligible readers up to Wanted; it can choose one while another eligible reader remains.
OneOpenPerReader and AtMostNeedStanding do not prohibit that serialization. The missing model
obligation is recorded as sprint-spec-fix-readcards-parallel-model, owing
`TestReadCardsGatesAllAvailableReadsInOneStep`: add an all-available-at-once property, a required
passing case and a serial-deal reversed witness, then replace this divergence with that TLA pin.
This proposed fix card needs coordinator admission; no existing pin or requirement is weakened.
