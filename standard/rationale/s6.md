## R-LAND-PARALLEL (H2)

The owner, 2026-10-18: "We've already talked about parallel merges for a month. You keep
forgetting." Read on 2026-10-18 (the first cold read of card sprint-spec-skeleton named each): the code
lands far more serially than the row allows, so the row is pinned only for the part that holds
(each stream its own batch on its own fork) and is otherwise a divergence, every serial point
owed a test by sprint-spec-fix-land-parallel (standard/pins/s6.tsv):

- the land loop (`cmd/nova-sprint/landloop.go`, `landCycle`) starts no pass while one runs ("one
  landing runs at a time"), and a pass picks its streams when it starts, so a stream queued
  during a pass waits for every other stream's gate in it, up to the landing deadline;
- the cuts of one (repository, base) lane are chained (`landpass.go`, `lane.prior`): each job
  waits for the previous job's cut;
- a base commit's gate has one writer (`baseGates`, one slot per base commit): two streams on
  one base commit gate one after the other;
- a built batch waits `landGrace` (30 s) for a higher-priority stream of its lane still in its
  merge phase;
- the width is capped (`landParallelDefault` = 4): the fifth stream queued waits for a slot;
- `--land-parallel 1` is accepted and merges the streams one after another.

Within a pass, streams on different lanes do merge side by side, and only one base's pushes go
one at a time; `cmd/nova-sprint/spec_land_parallel_test.go`
(`TestEachStreamLandsAsItsOwnBatchOnItsOwnFork`) pins that each stream is its own batch on its
own fork. The
git-backed lane tests (`TestALaneLandsWhileAnotherLanesCombinedGateBlocks`,
`TestLandAnotherBaseProgressesWhileFirstBaseGateWaits`) show the side-by-side half. The
across-pass serialization is a blocker finding of card sprint-spec-skeleton.
