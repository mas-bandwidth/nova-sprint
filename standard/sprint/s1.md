# s1. Introduction, terminology and conventions

## s1.1. Scope

This standard states what nova-sprint does: how cards are written and admitted, how the machine
deals them to rows, how attempts are worked, read and landed on their bases, how the machine
judges what it cannot decide and pushes every event to the rows it concerns, what the store
holds, where configuration comes from, and how the machine starts, stops and tells each seat
how to operate. It binds the machine, the verbs of the command line, the members and friends
that work cards, and the coordinator. It does not bind how a worker does a card's work inside
its own lane, beyond what it reports.

## s1.2. Key words

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT",
"RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be
interpreted as described in BCP 14 (RFC 2119, RFC 8174) when, and only when, they appear in
all capitals, as shown here.

## s1.3. Terminology

Each term below means one thing in every section, and no other word is used for it.

| Term | Meaning |
|---|---|
| machine | the running sprint: its server, its tick and its land loop, which make every mechanical move |
| tick | one pass of the machine over the store: it takes back, deals, promotes, judges and closes |
| member | a fleet computer enrolled in the sprint, which takes and works the cards dealt to its row |
| friend | an outside session, a model in its own harness, enrolled under a name, which works the cards dealt to its row |
| row | the place a member's or a friend's cards are dealt to, with a width |
| lane | one unit of a row's width: one work card, or two read cards |
| coordinator | the one seat that answers judgments and decides what the machine does not decide by rule |
| card | one unit of work with its brief |
| brief | a card's text: its header lines (repository, base, stream, needs, paths, tier, deadline) and its task |
| primary | the card a stream lands; its work cards and read cards are cut from it |
| work card | the card a worker takes to do a primary's work at one attempt |
| read card | the card a reader takes to read one attempt of a primary |
| attempt | one try at a primary's work, numbered from 1; a rework starts the next |
| head | the commit an attempt's work finished at |
| worker | the member or friend that works an attempt |
| reader | a member or friend dealt a read card |
| read | a reader's verdict on an attempt's head: ok or broken |
| deal | the tick's step that places ready cards on rows |
| take | a row's step that moves a dealt card from ready to working |
| need | a dependency without which a card cannot compile or run |
| order | a land-after relation between two cards of a stream that is not a need |
| stream | a named sequence of primaries that land on one base |
| base | the branch a stream lands on |
| landing | the step that merges a primary's head onto its base, gates it and pushes it |
| tier | the class of model a card needs: flash, pro, heavy or frontier, in that order from the lightest |
| level | a card's priority: blocker, critical, fix, high, normal or low |
| judgment | a decision the machine raises for the coordinator, open until answered |
| bound | a limit the machine enforces by itself |
| push | a message the machine sends to a row over the bus when an event happens |
| hook | a row's live subscription to its pushes, proven by the challenge |
| playbook | the text a verb prints that tells a seat how to operate: the coordinator's playbook and the worker playbook |
| epoch | one numbered start of the sprint; a clear begins the next |

## s1.4. Conventions

- **Actors.** Every requirement names the actor that holds it: the machine, the tick, the land
  loop, a verb, a member, a friend, a reader, a worker or the coordinator.
- **Time.** Time is an input. Every bound is measured on the sprint's clock, the time the step is
  given; no requirement depends on how long a step takes to run.
- **One writer.** The store changes only by a verb or by the machine. A requirement on "the
  store" is a requirement on the verb or the step that writes it.
- **Pins.** Every row that states an absolute requirement or prohibition is checked by a test, a
  model property or a constant, named in the section's pin file. A row whose pin is a divergence states
  the intent; the code does not hold it yet, and the pin names the work that brings the code to
  it. A divergence never weakens its row.
- **Hard rows.** A row marked (hard) is the owner's own requirement. A later revision clarifies a
  hard row or pins it, and never weakens or removes it.
- **Pending sections.** A section marked `Status: pending` is not yet written: its scope is not
  normative, and only the hard rows it carries bind.
