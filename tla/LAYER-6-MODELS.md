# Layer 6 models: scope, assumptions and reversed witnesses

The layer 6 models are `Run.tla` (chooser, scheduling, store contract, pusher), `RunClear.tla` (delivery across an epoch change), `Setup.tla` (the eight-step walk), `SetupChoices.tla`, and `SetupHandoff.tla` (the two-phase handoff). This file states what each covers, what it assumes, and what each reversed witness shows. A model result is a bounded TLC enumeration of the instance; it does not prove the implementation. The code is bound to the models by trace checks (`CHECK-LAYER6-TRACES.md` and the `*Trace-MAPPING.md` files).

Witness configurations are generated by `make-*-witnesses.py` into `witnesses/layer6/` and `*-runs.json` manifests; `run-layer6.py` runs a manifest and `ci-tlc.sh` runs all of them. A pass needs exit 0 and the completed, no-error marker. A safety witness needs exit 12 naming its exact invariant; a temporal witness needs exit 13 naming its exact property. Parse errors, timeouts and a different target all fail.

## Run.tla

The instance has two cards, up to two processes, three work operations, one recipient and three reports.

- PostgreSQL lock exclusivity is an input primitive represented by one owner. `OneChooser` does not prove exclusion across separate health-check and commit calls. Unobserved lock or hook loss permits one final Apply; observed loss stops later applies. `RunLockCheckRace` violates the stronger `CommitUnderCurrentLock` property on purpose and records this limit.
- Layer 3 owns ordering, packing, budget and carry. Run applies independently packed operations in order and returns whole refused ops next tick; it never splits a packed transaction. Each packed operation carries one card move in the instance. Multi-write atomicity and same-id replay belong to layer 1.
- A restart loses volatile history. Work derived from the store is replanned from a cold snapshot. Layer 4 facts must be requeryable by stable `(kind, card, sha)`: CI from the forge at a head, landing from git ancestry and the base tip, runner state from the store.
- `SendOK` requires exit 0 and a confirmed message id for the intended recipient. The cursor is saved after confirmation; a crash between the two permits duplicates. Delivery to a human is not implied.
- Dependent edges require accepted causal op ids. The instance has one dependency per edge; the code checks every `After` id, and empty means independent.
- The log abstraction has accepted events that all need the one recipient. Filtering unrelated or refused events, chunking, group deduplication and several recipients are covered by pusher unit and functional tests.
- Liveness assumes eventual stability (bounded reports and failures), weak fairness, a positive budget and eventual confirmed sends. It is not a wall-clock latency claim.
- A pusher summary caps a subject body at 4 KiB and 20 item lines; omitted items become a count and the `nova-sprint next` command, which must be able to list every omitted actionable obligation.

Configurations: `Run` (safety and eventual work and sends), `RunFailover` (one crash, PostgreSQL or hook loss, or hook failure), `RunReports` (three reports), `RunStopStart`, `RunInitiallyStopped`.

| Witness | What it shows |
|---|---|
| `RunLockCheckRace` | acquire, fold, lose the lock, Apply before noticing: the accepted limit above |
| `RunIgnoresObservedLoss` | applying after an observed loss is refused by the model |
| `RunFenceDropped` | applying a plan whose generation fence was dropped |
| `RunBudgetIgnored` | applying more operations than the budget |
| `RunCarryDropped` | discarding the carry loops forever on empty ticks |
| `RunRefusedLost` | forgetting a refused op loses its work (a genuine temporal violation) |
| `RunCursorBeforeSend` | saving the cursor before the send is confirmed |
| `RunPushBeforeCommit` | sending an event that is not yet committed |
| `RunEdgeBeforeCommit` | dispatching a dependent edge before its op is accepted |
| `RunTickWhileStoppedGate`, `RunTickWhileStoppedFence` | planning after an observed stop, and an accepted tick write while stopped (`NoTickWhileStopped`) |
| `RunStoppedTickGateDropped` | the planner guard removed: `NoTickAfterObservedStop` |
| `RunStoppedFenceDropped` | read running, Stop, fold, apply with a stale fence: `NoAcceptedTickWhileStopped` |

### Stopped service

A stopped machine plans nothing: the planner action is disabled after observing a stop. A running observation can race a later Stop, so accepted tick writes also need the store's atomic `AtSeq` condition. `CaptureFence` saves the observed sequence once per pending operation; `sequenceFresh` and `fenceFrozen` model its saved `AtSeq`. Every physical append, including refusal and cursor metadata, invalidates both. A later `ReadControl` refreshes the observation and never replaces a captured fence. Reports stay independent operations; Stop preserves pending work and carry; the pusher keeps delivering committed events. Edge dispatch is not atomically fenced with Stop, so the model does not claim no send after Stop. An unknown outcome that already committed, and its Replay, are outside the model.

## RunClear.tla

Every committed notice is eventually sent, or cancelled by a later Clear and covered by a confirmed per-recipient Clear summary. A cursor cannot pass a notice with neither coverage, or a Clear whose summary was not confirmed. Summary duplicates after a crash are allowed (at-least-once delivery). The summary text is `epoch <n> cleared: <k> pending notices dropped (some may have reached you); run nova-sprint next`; the count is cursor-pending notices, not certainly undelivered ones.

A snapshot observes an epoch but does not fence a later bus send, so an old notice already prepared can arrive after the Clear commits. An old-epoch cursor write is refused and the next scan suppresses the old backlog and emits the summary. The verb a notice names must refuse a mutation from another epoch. Clear and external sends are not atomically exclusive. The instance has two notices, one Clear, one recipient and at most one crash.

| Witness | What it shows |
|---|---|
| `RunClearSummaryLost` | cursor passes a cancelled notice with no summary (`CursorHasCoverage`) |
| `RunClearCursorEarly` | cursor advances before the summary is confirmed (`CursorHasCoverage`) |
| `RunClearInFlight` | an old notice is sent after the Clear without observing it (`NoOldSendAfterClear`) |
| `RunClearCountAmbiguous` | a confirmed-but-cursor-pending notice is counted in the summary (`ClearCountIsUndelivered`) |
| `RunClearOriginalCancelled` | the unconditional property `EveryOriginalSent` cannot hold across a Clear |

The last two are accepted limits, not injected bugs.

## Setup.tla

The model has all eight steps. Every invocation probes from step one; "verified" is evidence from this invocation, never a persistent completion map. A service can regress after its probe, so the walk is not a distributed transaction across the eight services. `AskedOnce` counts durably stored answers, not prompts interrupted before storage; interrupted input can need re-entry. No secret bytes are modelled, only allowed sinks (the secret setter's stdin). Liveness assumes external prerequisites become repairable and humans supply the required answers. The overlapping pastes of two people need not be equal, so `AskedOnce` describes a serialised walk, not a ban on every duplicate prompt under lease loss.

Witnesses: `SetupUnverified` (a first probe marks a missing prerequisite verified), `SetupAnswersLost` (a crash forgets a saved answer and asks twice), `SetupResumeSkips` (restart at step eight), `SetupKeyInArgv` (a key recorded in argv as its sink). `SetupChoices*` cover the choice step, with the `none` and `configured` walks and the re-prompt and key-required witnesses.

## SetupHandoff.tla

Two children, no lease spanning both. Phase 1 acquires its lease, saves the credential and schema, persists the record while still holding the lease, and releases. Phase 2 prevalidates the record and readiness, probes step one, reacquires, revalidates under the lease, freshly probes step one, then performs the effect, which abstracts the remaining full walk (it never permits skipping steps 2 to 8). Reuse after completion or a crash clears fresh and validated state and restarts phase 2; a crash before the parent receives an id restarts phase 1; durable prerequisites remain.

The record abstracts an immutable inactive policy-data object with a format version, epoch, actor and a digest of the non-secret arguments. Id randomness, JSON, hashing, canonicalisation, storage fences and permissions are implementation obligations. `ValidatedCurrentRecord` holds at validation under the lease, not atomically against a later Clear. `ParentProtocolOnly` restricts the parent's alphabet to opaque ids and status; it does not prove memory, argv, environment or output confidentiality. Liveness permits done or refused, assumes fair retries, and covers zero or one crash plus one reuse.

| `SetupHandoffWrongSeat` | `EffectsOrdered`: effect under the admin seat |
| `SetupHandoffRefusedEffect` | a stale epoch with a competing holder still produces an effect |
