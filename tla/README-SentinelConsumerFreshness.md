# Consumer receipt freshness

This P8 companion adds the two concrete schedules missing from SentinelRelease, without changing that model or its 21 measured cases. Runtime mapping: ConsumerBarrierInput/consumer receipt validation in internal/sprint/sentinel_dev.go and per-(repo,trunk) callback observation caching in cmd/nova-sprint/sentinel_dev.go. Actual code names and source freeze are recorded in the handoff after author integration.

Two consumers in different streams share one repository/trunk. A callback reads its input table once and performs a separate successful branch merge for each consumer. The first freshly fetched development tip is retained for that key throughout this callback. Remote Git may advance after that fetch; it is intentionally permitted to deal using the captured snapshot until a later callback observes the newer tip. No claim of distributed Git/store atomicity or an unobserved latest head is made.

Each receipt includes a ghost exact input card key and the captured ordered vector of relevant released barriers. A vector item represents ID, revision, release state/kind, producing closure, recorded targets and position. Producing-closure evidence here means the released sentinel's captured declaration/revision, not a proof of its entire expanded current producing graph. The concrete vector growth is one newly inserted/released positional barrier while the existing consumer's epoch/ID/revision remain unchanged. Fenced store retry must compare the receipt vector with its current relevant vector. This finite model does not explore every mutation of every vector field; equality is the abstraction of the concrete immutable input check.

BrokenBarrierReplay drops only this vector equality guard. Capture A, finish callback, insert/release B, then deal with the unchanged card and old A receipt must violate DealsUseCurrentBarrierVector. BrokenMixedObservation restores per-consumer fetches: first consumer observes D1; remote advances; second same-key consumer observes D2; retaining the earlier D1 receipt and per-consumer success map must violate DealsUseKnownCallbackSnapshot when the first consumer is dealt. Its configuration deliberately waits for an invalid deal rather than checking the mixed snapshot immediately. The normal control also checks CallbackUsesOneObservedTip.

The positive reversed reachability controls prove that normal deals are reachable and a first callback captures D1 and a subsequent callback captures D2 (the witness preserves the previous callback tip as ghost history). Bounds are two consumers, two callbacks, two observed tips and one inserted barrier. There is no fairness/liveness claim, arbitrary dynamic graph, drop/re-add, epoch advancement, Git failure, or fabricated ancestry model here. Existing SentinelRelease and runtime tests cover their stated separate scopes; this is not a runtime refinement proof.

Five cases are registered as required in group sentinelconsumerfreshness. Source review is not measured proof. Linux-only supported tlacheck receipts, current fingerprints and preserved history are required before a validation claim.
